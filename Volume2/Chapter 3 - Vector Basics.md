# 第3章 ベクトルの基本

**この章のゴール**

ベクトルを数の並びとして扱いながら、長さ・距離・足し算・embeddingとのつながりを説明できるようになること。

## 3.1 ベクトルは「数の並び」である

前章では、ベクトルは「数を一列に並べたもの」だと説明しました（`[1.0, 2.0, 3.0]` は3つの数を持つ3次元ベクトル）。

機械学習では、ベクトルは非常によく出てきます。たとえば、ある人の特徴を `[身長, 体重, 年齢] = [170.0, 65.0, 30.0]` のように、複数の数値をひとまとめにして扱えます。

Transformerでもベクトルは基本単位です。文章そのものを直接扱うのではなく、まずトークンをベクトルに変換します（`dog → [0.12, -0.44, 0.87, 0.03]`）。この数値は人間が手で決めるものではなく、モデルが学習によって「このトークンをどのようなベクトルで表すとよいか」を調整していきます。

```text
トークン → ベクトル → ニューラルネットワークで処理
```

そのため、ベクトルを理解することは、Transformerを理解するための第一歩です。

## 3.2 ベクトルは「意味を持った方向」としても見られる

ベクトルは、単なる数の並びとして見ることもできますが、「方向」として見ることもできます。たとえば2次元のベクトル `[1.0, 2.0]` は、平面上で「x方向に1.0、y方向に2.0」進む矢印として見られます。

2次元や3次元なら図としてイメージしやすいですが、機械学習では100次元、512次元、768次元のような高次元ベクトルが普通に出てきます。高次元ベクトルは図として描けませんが、考え方は同じで、「ベクトルは、高次元空間の中の点または方向を表している」と考えます。

Transformerでは、トークンを高次元ベクトルとして表します（`d_model = 768` なら各トークンは768個の数）。この数は人間が直接意味を読むためのものではありませんが、モデルにとっては、そのトークンの意味や使われ方を表す情報になります。理想的には、意味が近い単語は近いベクトルになることが期待されます（dog と cat は近い、dog と car は少し遠い、dog と democracy はもっと遠い）。ベクトルは、ただの数の並びであると同時に、「意味を持った位置」や「意味を持った方向」としても見られます。

## 3.3 ベクトルの足し算

ベクトル同士は足し算できます。ただし、足し算できるのは同じ次元数のベクトル同士で、対応する要素同士を足します。

```text
a = [1.0, 2.0, 3.0], b = [4.0, 5.0, 6.0]
a + b = [1.0+4.0, 2.0+5.0, 3.0+6.0] = [5.0, 7.0, 9.0]
```

ベクトルの足し算は、Transformerでもよく出てきます。代表的なのは `token embedding + positional encoding` です。Transformerは各トークンをembedding vectorに変換しますが、それだけでは「何番目のトークンか」という位置情報がありません。そこで、トークンのベクトルに、位置を表すベクトルを足します。

```text
入力ベクトル = トークンのベクトル + 位置のベクトル
（例：[0.10, 0.20, 0.30] + [0.01, 0.00, -0.01] = [0.11, 0.20, 0.29]）
```

このように、ベクトルの足し算によって、複数の情報を1つのベクトルにまとめられます。残差接続 `x + Sublayer(x)` でもベクトルの足し算が使われます。これは、元の入力 `x` にサブレイヤーの出力を足しています。ベクトルの足し算は、Transformerの中で非常に基本的な操作です。

## 3.4 ベクトルのスカラー倍

ベクトルは、スカラー（1つの数）を掛けることができます。各要素にそのスカラーを掛けます。

```text
a = [1.0, 2.0, 3.0]
2.0 * a = [2.0, 4.0, 6.0]
0.5 * a = [0.5, 1.0, 1.5]
```

ベクトルをスカラー倍すると、向きは基本的には同じで、長さが変わります（2.0倍で長く、0.5倍で短く、-1.0倍で向きが反対に）。

Transformerでは、スカラー倍もさまざまな形で出てきます。たとえばAttentionの `QK^T / sqrt(d_k)` は、スコア行列を `1 / sqrt(d_k)` 倍していると見られます。これはAttention scoreの大きさを調整するためです。softmaxに入れる前の値が大きすぎるとsoftmaxの出力が極端になりすぎることがあるので、`sqrt(d_k)` で割って抑えます。今は「スカラー倍は、ベクトルや行列の値の大きさを調整する操作である」と理解しておけば十分です。

## 3.5 ベクトルの長さ

ベクトルには「長さ」があります。2次元のベクトルなら、図に描いたときの矢印の長さです。`a = [3.0, 4.0]` の長さは、三平方の定理で `sqrt(3.0^2 + 4.0^2) = sqrt(25.0) = 5.0` です。

3次元以上でも考え方は同じで、`a = [a1, a2, ..., an]` の長さは `sqrt(a1^2 + a2^2 + ... + an^2)` です（`[1.0, 2.0, 2.0]` なら `sqrt(1+4+4) = 3.0`）。

機械学習では、ベクトルの長さは「値の大きさ」や「スケール」を表すものとして重要です。長さが大きすぎたり小さすぎたりすると学習が不安定になることがあるので、ニューラルネットワークでは値のスケールを整えることが重要になります。Transformerの Layer Normalization も、そのようなスケール調整と関係があります。また、内積やcosine similarityを理解するときにもベクトルの長さは重要です（特にcosine similarityでは、向きだけを比較するために長さで割って正規化します）。ベクトルの長さは今後何度も出てくる基本概念です。

## 3.6 ベクトル同士の距離

ベクトルは点として見ることもでき、その場合、2つのベクトルの間には「距離」があります。距離は、まず差を取り、その差のベクトルの長さです。

```text
a = [1.0, 2.0], b = [4.0, 6.0]
b - a = [3.0, 4.0]
距離 = sqrt(3.0^2 + 4.0^2) = 5.0
```

機械学習では、ベクトル同士の距離は「どれくらい違うか」を表すために使われます。単語のembeddingでは、意味が近い単語は近い場所にあることが期待されます（dog と cat は距離が近い、dog と car は遠い）。実際の高次元空間では図で見ることはできませんが、「意味が似ているものはベクトル空間上で近く、違うものは遠くにある」という考え方は同じです。

ただし、TransformerのAttentionでは、距離そのものよりも、内積による「相性」の計算が中心になります。距離は「どれくらい離れているか」、内積は「どれくらい同じ向きを向いているか／相性がよいか」を測ります。内積については次章で詳しく扱います。

## 3.7 単語をベクトルで表すということ

自然言語処理では、単語やトークンをベクトルで表します。これはTransformerを理解する上で非常に重要です。なぜなら、ニューラルネットワークは文字や単語をそのまま理解できず、扱えるのは基本的に数値だからです。

そのため、文章を扱うには、まず数値に変換します。

```text
文章 → トークン列 → トークンID列 → embedding vector列
```

「I love dogs」をトークンに分け（["I", "love", "dogs"]）、各トークンにIDを割り当て（"I"→12、"love"→45、"dogs"→98）、整数の列 `[12, 45, 98]` にします。ただし、この整数ID自体には数値としての大小に意味はありません（"dogs"のID 98 が "love" のID 45 より大きい意味を持つわけではない）。トークンIDはあくまで辞書の番号です。

そこで、各トークンIDをベクトルに変換します。この変換を行うのがembeddingで、PyTorchでは `nn.Embedding` を使います。

```python
import torch
import torch.nn as nn

vocab_size = 100
d_model = 4

embedding = nn.Embedding(vocab_size, d_model)
token_ids = torch.tensor([12, 45, 98])
x = embedding(token_ids)

print(x.shape)   # torch.Size([3, 4])  3個のトークン、各4次元ベクトル
```

出力のshape `[3, 4]` は `[seq_len, d_model]` です。このように、embeddingによってトークンIDはベクトル列に変換され、Transformerはこのベクトル列を入力として処理します。

## 3.8 embeddingの直感

embeddingは、トークンをベクトルに変換する仕組みですが、単に変換しているだけではありません。重要な点は、学習によって調整されることです。

最初、embeddingの値はランダムに初期化されます（`dog` も `cat` も最初は特に意味のある値ではない）。しかし、学習が進むにつれて、モデルにとって役に立つ表現へと変わっていきます。言語モデルでは文脈から次のトークンを予測するように学習し、その過程で、似たような文脈で使われる単語は似たようなベクトル表現を持つようになることがあります（dog・cat・horse は近く、car・train・airplane は別のまとまりを作る、など）。

もちろん、現実のembedding空間はもっと複雑です。単語の意味は1種類ではありません（`bank` は「銀行」にも「川岸」にもなる）。現代のTransformerでは、単語そのものに固定の意味ベクトルを与えるだけでなく、文脈の中でベクトル表現を変化させます。「I went to the bank to deposit money.」と「I sat on the bank of the river.」では、同じ `bank` でも意味が違います。Transformerは、Self-Attentionによって周囲のトークンを参照しながら、各トークンの表現を更新します。

つまり、最初のembeddingは「出発点」です。その後、Transformerの層を通ることで、文脈を反映したベクトル表現に変わっていきます。

```text
token embedding → Self-Attention → 文脈を反映したベクトル → さらに次の層へ
```

embeddingはTransformerの入口で、すべての処理は、トークンをベクトルに変換するところから始まります。

## 3.9 PyTorchでベクトル演算を確認する

PyTorchを使って、ベクトルの基本操作を確認します。

```python
import torch

a = torch.tensor([1.0, 2.0, 3.0])
b = torch.tensor([4.0, 5.0, 6.0])

print("a + b:", a + b)                              # tensor([5., 7., 9.])
print("b - a:", b - a)                              # tensor([3., 3., 3.])
print("2.0 * a:", 2.0 * a)                          # tensor([2., 4., 6.])
print("length of a:", torch.norm(a))               # tensor(3.7417)  sqrt(1+4+9)=sqrt(14)
print("distance between a and b:", torch.norm(b - a))  # tensor(5.1962)  sqrt(27)
```

`torch.norm(a)` はベクトルの長さ（`sqrt(1.0^2 + 2.0^2 + 3.0^2) = sqrt(14) ≈ 3.7417`）、`torch.norm(b - a)` は2つのベクトルの距離（差のベクトル `[3,3,3]` の長さ `sqrt(27) ≈ 5.1962`）です。

この章の段階では、PyTorchの細かい書き方をすべて覚える必要はありません。重要なのは、次の対応です。

```text
ベクトルの足し算 → a + b / 引き算 → b - a / スカラー倍 → 2.0 * a
ベクトルの長さ → torch.norm(a) / ベクトル同士の距離 → torch.norm(b - a)
```

これらは、Transformerの中でも基礎になる操作です。

## 3.10 PyTorchでembeddingを確認する

次に、embeddingをPyTorchで確認します。語彙サイズと各トークンのベクトルの次元数を決め、embedding層を作り、トークンIDを通します。

```python
import torch
import torch.nn as nn

vocab_size = 10
d_model = 4

embedding = nn.Embedding(vocab_size, d_model)

# 単一の文（3トークン）
token_ids = torch.tensor([2, 5, 3])
print(embedding(token_ids).shape)   # torch.Size([3, 4])  [seq_len, d_model]

# バッチ付き（2文、各3トークン）
batch_ids = torch.tensor([
    [2, 5, 3],
    [1, 4, 7],
])
print(batch_ids.shape, "->", embedding(batch_ids).shape)
# torch.Size([2, 3]) -> torch.Size([2, 3, 4])  [batch_size, seq_len, d_model]
```

単一の文（3トークン）なら出力は `[3, 4]`（`[seq_len, d_model]`）、バッチ付き（2文）なら `[2, 3, 4]`（`[batch_size, seq_len, d_model]`）です。このshapeは、Transformerの基本形です。

```text
token_ids: [batch_size, seq_len]
 ↓ embedding
x:         [batch_size, seq_len, d_model]
```

まとめると、embeddingは「整数IDの列 → ベクトルの列」という変換をしています。このコードは、Transformerの最初の入口に相当します。Transformerは、まずトークンIDをembeddingによってベクトルに変換し、そのベクトル列をSelf-AttentionやFeed Forward Networkで処理していきます。

## 3.11 まとめ

この章では、ベクトルの基本を学びました。ベクトルは、数を一列に並べたものですが、機械学習では単なる数の並びとしてだけでなく、「特徴」や「意味」を表すものとして扱います。単語やトークンはembeddingによってベクトルに変換され（`token → embedding vector`）、文章はまずトークン列になり、次にベクトル列になります（文章 → トークン列 → トークンID列 → embedding vector列）。

ベクトルには、足し算・引き算・スカラー倍・長さ・距離といった基本操作があります。ベクトルの足し算は複数の情報を混ぜるために使え（`token embedding + positional encoding`）、スカラー倍は値の大きさを調整するために使えます（`QK^T / sqrt(d_k)`）。ベクトルの長さや距離は、ベクトル空間の中で「どれくらい大きいか」「どれくらい離れているか」を考えるために使います。

embeddingを理解する上では、「意味が近いものは、ベクトル空間上でも近くにある」という直感が重要です。ただし、Transformerでは、最初のembeddingだけで意味が決まるわけではなく、Self-Attentionによって各トークンのベクトルは文脈を反映した表現へと更新されていきます。

この章で特に重要なのは、次のことです。

```text
Transformerはトークンをベクトルとして扱う
ベクトルは数値の並びであり、意味や特徴を表すことができる
embeddingはトークンIDをベクトルに変換する
```

次章では、内積について学びます。内積は、Attentionを理解するための非常に重要な道具です。特に Self-Attention では、QueryとKeyの内積によってトークン同士の相性を計算します（Query と Key の内積 → トークン同士の相性スコア）。そのため、内積を「ただの計算」としてではなく、「ベクトル同士の相性を測る操作」として理解することが重要です。
