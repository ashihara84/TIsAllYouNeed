# 第1章 なぜTransformerに数学が必要なのか

**この章のゴール**

Transformerの数式を「難しい記号の集まり」ではなく、ベクトル・行列・softmax・重み付き和の組み合わせとして見られるようになること。

## 1.1 Transformerは巨大な数式ではなく、ベクトル計算の積み重ねである

『Attention Is All You Need』を初めて読むと、Transformerはとても難しい数学でできているように見えるかもしれません。たとえば、論文には次のような式が出てきます。

```text
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V
```

ぱっと見ると、いかにも数学っぽく見えます。しかし、Transformerを実装するために必要な見方は、そこまで難しくありません。Transformerの中で行われているのは、大きく言えば次の計算の繰り返しです。

```text
ベクトルを作る → 行列を掛ける → 内積を計算する → softmaxで重みに変える → 重みに応じてベクトルを混ぜる
```

つまりTransformerは、巨大で謎めいた数式の塊ではなく、たくさんのベクトル計算と行列計算を積み重ねたものです。

重要なのは、数式を見たときに「これは何を入力にしているのか」「何を出力しているのか」「shapeはどう変わるのか」「この計算は何のためにあるのか」を読めるようになることです。

数学を専門的に学ぶ必要はありません。行列の固有値や線形空間の厳密な定義を知らなくても、小さなTransformerを実装できます。微分の厳密な証明を知らなくても、勾配降下法やバックプロパゲーションの大まかな意味を理解できます。確率論を深く知らなくても、softmaxの出力を「次のトークンの確率分布」として扱えます。

この教科書で目指すのは、数学者になることではありません。Transformerの数式を見たときに、「これはトークン同士の相性を計算しているんだな」「これは重みを作っているんだな」「これは複数のベクトルを混ぜているんだな」と読めるようになることです。

## 1.2 論文の数式を読むために必要な数学

『Attention Is All You Need』の中心にある数式は、Attentionの式です。この式を読むために必要な数学は、主に次の6つです。

```text
ベクトル / 行列 / 内積 / softmax / 平方根 / shape
```

ひとつずつ見ると、それほど難しくありません。

**ベクトル**：Transformerでは、単語やトークンをそのまま扱うのではなく、数値の並びとして扱います。たとえば「犬」を `[0.12, -0.44, 0.87, 0.03]` のような数値の並びで表します。これがベクトルです。実際のTransformerでは、数百〜数千個の数値を使うことが多いです。

**行列**：行列は、ベクトルを変換するために使います。Transformerでは、入力ベクトルから Query・Key・Value という3種類のベクトルを作るときに行列を掛けます（実装では線形層として書くことが多い）。

**内積**：内積は、2つのベクトルがどれくらい似ているか、相性がよいかを測る計算です。Attentionでは、QueryとKeyの内積を計算します。これは、ざっくり言えば「このトークンは、あのトークンにどれくらい注目すべきか」を計算しています。

**softmax**：QueryとKeyの内積でトークン同士の相性スコアが出ますが、そのままでは扱いにくいので、softmaxで「合計が1になる重み」に変換します。たとえばスコア `[2.0, 1.0, 0.1]` は、softmaxで `[0.66, 0.24, 0.10]` のような重みになります。これは「1番目を強く見る、2番目を少し見る、3番目はあまり見ない」という意味に解釈できます。

**平方根**：Attentionの式には `QK^T / sqrt(d_k)` のように `sqrt(d_k)` で割る部分があります。これは内積の値が大きくなりすぎるのを防ぐための調整です。今は厳密な理由を理解しなくても、「softmaxに入れる前に、スコアの大きさを調整している」と理解しておけば十分です。

**shape**：Transformerを実装するとき、もっとも重要な感覚のひとつがshape（テンソルの形）です。

```text
ベクトル: [4]
行列: [3, 4]
バッチ付きのトークン列: [batch_size, seq_len, d_model]
```

実装では、「このテンソルのshapeは何か」「行列積の結果のshapeはどうなるか」「softmaxはどの次元にかけるのか」を追える必要があります。実装で詰まる原因の多くは、数学の高度な理解不足ではなく、shapeの理解不足です。そのため、この教科書では「数式の意味」と同じくらい「shapeを読むこと」を重視します。

## 1.3 実装で本当に必要になる数学

Transformerを実装するために必要なのは、大学数学を広く学ぶことではなく、実装中に出てくる計算を理解することです。たとえば、次のようなコードが出てきます。

```python
q = self.w_q(x)
k = self.w_k(x)
v = self.w_v(x)

scores = q @ k.transpose(-2, -1)
scores = scores / math.sqrt(d_k)
weights = torch.softmax(scores, dim=-1)
out = weights @ v
```

このコードを理解するために必要なのは、「線形層は何をしているのか」「行列積 `@` は何をしているのか」「なぜ `k` を転置するのか」「なぜ `sqrt(d_k)` で割るのか」「softmaxは何をしているのか」「`weights @ v` は何をしているのか」といった知識です。

つまり、実装で必要な数学は、コードと直接対応しています。数学を学ぶときも、「この数学はどのコードに対応しているのか」「この概念はTransformerのどこで使われるのか」と考えるとよいです。

- 内積を学ぶ目的は、「Attentionでは、QueryとKeyの内積でトークン同士の相性を計算している」と理解すること。
- 行列積を学ぶ目的は、「複数のトークンをまとめて一度に変換するために、行列積を使っている」と理解すること。
- 微分を学ぶ目的は、「損失を小さくするために、各パラメータをどちら向きに動かせばよいかを知る」と理解すること。
- 確率分布を学ぶ目的は、「言語モデルは、次のトークン候補それぞれに確率を割り当てている」と理解すること。

このように、実装から逆算して数学を学ぶのが、この教科書の方針です。

## 1.4 証明よりも「形」と「意味」を重視する

数学の教科書では、定義、定理、証明が重視されます。それは数学を専門的に学ぶ上では重要ですが、Transformerを実装するための数学では、最初から証明を重視しすぎると遠回りになります。

たとえば行列積について、数学的に厳密な定義を学ぶこともできますが、Transformer実装でまず必要なのは次の感覚です。

```text
[seq_len, d_model] の入力に [d_model, d_k] の重みを掛けると [seq_len, d_k] の出力になる
```

つまり、まずはshapeが追えることが大事です。softmaxも、性質を厳密に証明するより、「スコアの列を合計1の重みに変換する」「大きいスコアほど大きい重みになる」「Attentionでは、どのトークンを見るかを決めるために使う」がわかる方が大事です。微分も、極限の定義から厳密に理解するより、「少し動かしたときに値がどう変わるかを見る道具」「勾配と逆向きに動けば損失を下げられる」がわかる方が大事です。

もちろん、厳密な理解が不要という意味ではありません。学ぶ順番として、次の流れがよい、ということです。

```text
まず意味を理解する → 次にshapeを追う → 次にコードで動かす → 最後に必要なら厳密な定義に戻る
```

この教科書では、数式を出すときも、できるだけ「数式・意味・実装上のshape」の3つをセットで説明します。たとえばAttentionの式は、次のように読みます。

```text
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V
```

これは数式としては短いですが、中身は「QとKの内積でトークン同士の相性を計算する → sqrt(d_k)で割ってスコアの大きさを調整する → softmaxで相性スコアを重みに変換する → その重みに応じてVを混ぜる」という処理です。さらにshapeで見ると、次のようになります。

```text
Q: [seq_len, d_k] / K: [seq_len, d_k] / V: [seq_len, d_v]
QK^T: [seq_len, seq_len]
softmax(QK^T / sqrt(d_k)): [seq_len, seq_len]
softmax(QK^T / sqrt(d_k))V: [seq_len, d_v]
```

このように、数式を「意味」と「shape」に分解して読めるようになることが、この教科書の大きな目標です。

## 1.5 この教科書で扱う範囲

この教科書で扱うのは、Transformerを実装するための最低限の数学です。具体的には、次の内容を扱います。

```text
スカラー / ベクトル / 行列 / テンソル / shape / 内積 / 行列積 / 転置 / 線形変換
softmax / 確率分布 / cross entropy / 微分 / 偏微分 / 勾配 / 勾配降下法 / 連鎖律 / 正規化 / Attentionの数式
```

これらは、Transformerを理解する上で何度も出てきます。ベクトルと行列は embedding や線形層（token → embedding vector → Q/K/V）で、内積は Attention（QueryとKeyの相性）で、softmaxは Attention weight や次トークン予測で、確率分布は言語モデルの出力で、cross entropy は学習時の損失関数で、微分と勾配はパラメータ更新で、正規化は Layer Normalization で使います。

この教科書では、それぞれの数学を単独で説明するのではなく、Transformerとの関係を意識しながら説明します。内積なら「なぜAttentionで内積を使うのか」まで、softmaxなら「なぜAttention weightにsoftmaxを使うのか」まで、微分なら「ニューラルネットワークはどうやって学習するのか」まで説明します。

この教科書を読み終えたときに目指す状態は、次のようなものです。

```text
Transformerの数式を見て、何をしているか大まかに説明できる
PyTorchのテンソル計算でshapeを追える
Attentionの式を日本語で説明できる
softmaxやcross entropyがどこで使われるかわかる
勾配降下法によってモデルが学習する流れを説明できる
```

この状態になれば、次の「ニューラルネットワークの基本」（第3巻）に進む準備ができています。

## 1.6 この教科書で扱わない範囲

この教科書は、数学全体を体系的に学ぶための本ではありません。そのため、あえて扱わない内容もあります。

```text
線形代数の厳密な公理 / ベクトル空間の抽象的な定義 / 固有値・固有ベクトルの詳細
行列式の理論 / 多変数微分の厳密な証明 / 測度論的な確率論 / 最適化理論の詳細
```

これらは重要な数学ですが、最初にTransformerを理解し、自分で小さく実装するためには必須ではありません。もちろん、将来的に深く学ぶ価値はあります（最適化理論を学べばAdamなどのoptimizerをより深く理解でき、線形代数を深く学べばembedding空間や表現学習についてより高度に考えられます）。しかし、最初からそこまで広げると、Transformerにたどり着く前に学習範囲が広がりすぎます。

この教科書では、目的を絞ります。目的は、`Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V` という式を読めるようになり、コードに落とせるようになり、この式がTransformer全体の中でどのような役割を持つのかを理解することです。そのため、「数学として美しい体系」よりも、「Transformerを理解するために必要な道具」として数学を扱います。

## 1.7 この章のまとめ

この章では、Transformerを理解するために、なぜ数学が必要なのかを説明しました。

重要なのは、Transformerに必要な数学は、最初から高度な数学ではないということです。必要なのは、ベクトル・行列・内積・softmax・確率分布・微分・勾配・shape といった基礎です。

Transformerの数式は一見難しそうに見えますが、実際には「ベクトルを変換する → トークン同士の相性を計算する → softmaxで重みにする → 重みに応じて情報を混ぜる → 損失を計算する → 勾配でパラメータを更新する」という処理の組み合わせです。

この教科書では、数学を厳密な証明中心ではなく、意味・shape・実装との対応を中心に学びます。特に大事なのは、数式を見たときに「これは何を入力にしているのか」「何を出力しているのか」「shapeはどう変わるのか」「Transformerのどこで使われるのか」を考えることです。

次章では、まずもっとも基本になる「スカラー」「ベクトル」「行列」「テンソル」について学びます。Transformerでは、すべてのデータが最終的にテンソルとして扱われます。そのため、次章で学ぶshapeの感覚は、今後のすべての章の土台になります。
