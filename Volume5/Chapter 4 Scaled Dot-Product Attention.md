# 第4章　スケール付き内積 Attention

**この章でわかること**

- QK^T で相性を測る（shape を追う）
- `sqrt(d_k)` で割る理由を、具体的に
- softmax で重みにし、V を重み付き和にする
- `Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V` を関数として実装する

この章で、Attention の中心式が完成します。

第2章の核（重み付き和）と、第3章の役割分担（Q/K/V）を、ついに1つの式にまとめます。

このシリーズで、いちばん大切な式が、この章で書けるようになります。

### 4.1　QK^T で相性を測る

第3章で、各トークンの Query と Key が、得られました。

相性スコアは、Query と Key の **内積** で測ります。

第2巻4章の回収です。

内積は「相性＝似ている度合い」を測る計算でした。

あるトークン `i` の Query と、トークン `j` の Key の内積。

これが、「`i` が `j` にどれだけ注目すべきか」の、生スコアになります。

これを、全ペアについて、まとめて計算するのが、行列積 `QK^T` です。

shape を追いましょう。

```text
Q : [L, d_k]
K : [L, d_k]  →  K^T : [d_k, L]    （転置）
QK^T : [L, L]   … 全トークン対の相性スコア
```

`Q` が `[L, d_k]`、`K` を転置した `K^T` が `[d_k, L]`。

これらを掛けると、`[L, L]` になります（第2巻5章の行列積のルール）。

この `[L, L]` の `(i, j)` 成分が、「トークン `i` の Query」と「トークン `j` の Key」の内積。

つまり、`i` から見た `j` への相性です。

3トークンなら、`[3, 3]` の表になります。

```text
        Key0   Key1   Key2
Query0  s00    s01    s02
Query1  s10    s11    s12
Query2  s20    s21    s22
```

`s12` は、「トークン1 が トークン2 にどれだけ注目するか」の生スコア、というわけです。

第2巻5章で「QK^T の shape を追う」を学んだのは、この瞬間のためでした。

そして、1回の行列積で、全トークン対の相性が、一気に出ます。

これが、第4巻11章で強調した「並列性」です。

RNN のように、1つずつ計算する必要は、ありません。

```python
import torch
Q = torch.randn(3, 8)   # [L=3, d_k=8]
K = torch.randn(3, 8)
scores = Q @ K.transpose(-2, -1)   # [3, 3]
print(scores.shape)                # torch.Size([3, 3])
```

### 4.2　`sqrt(d_k)` で割る理由

`QK^T` のスコアは、そのまま softmax に入れると、問題が起きます。

なぜでしょうか。

`d_k`（Q/K の次元）が大きいほど、内積は、多くの項の和になります。

内積は、各要素を掛けて全部足すものでした（第2巻4章）。

`d_k` が64なら、64個の積を足します。

`d_k` が512なら、512個。

項が多いほど、和の値は、大きくなりがちです。

スコアの絶対値が大きくなりすぎると、何が起きるでしょうか。

softmax の出力が、極端になります。

具体例で見ましょう。

スコアが `[2, 1, 0]` のときと、その10倍の `[20, 10, 0]` のときを、比べます。

```text
softmax([2, 1, 0])   ≈ [0.67, 0.24, 0.09]   （ほどよく分散）
softmax([20, 10, 0]) ≈ [0.9999, 0.00005, ~0] （1つにほぼ集中）
```

スコアが大きいと、最大のものにほぼ1、他にほぼ0、という「とがりすぎた」分布になります。

これが、なぜ困るのでしょうか。

softmax が極端にとがると、その付近では、傾き（勾配）がほとんど0になります（第4巻・第3巻で見た、softmax の性質）。

勾配がほぼ0だと、学習が進みません。

そこで、スコアを `sqrt(d_k)` で割って、スケールを整えます。

```text
scores = QK^T / sqrt(d_k)
```

たとえば `d_k=64` なら、`sqrt(64) = 8` で割ります。

これにより、`d_k` が大きくても、スコアが暴れず、softmax がほどよい分布を出せます。

論文の式に `sqrt(d_k)` が入っているのは、この安定化のためです（第2巻7章・14章で触れた、あの割り算です）。

### 4.3　softmax で重みにし、V を重み付き和にする

スケールしたスコアを、softmax に通すと、合計1の **注目の重み** になります。

第2章の核そのものです。

```text
weights = softmax(QK^T / sqrt(d_k))     … [L, L]、各行が合計1
```

`weights` の `i` 行目は、「トークン `i` が、各トークンにどれだけ注目するか」を表す重みです。

ここで、softmax を取る方向（`dim`）に、注意が要ります。

softmax は、最後の次元（`dim=-1`）に対して取ります。

`[L, L]` の各行（各 Query）ごとに、全 Key への重みが、合計1になるようにするのです。

```text
weights の各行が、合計1:
        Key0   Key1   Key2
Query0  0.5    0.3    0.2    （合計1）
Query1  0.1    0.8    0.1    （合計1）
Query2  0.2    0.2    0.6    （合計1）
```

最後に、この重みで、Value を重み付き和にします。

```text
出力 = weights @ V     … [L, L] @ [L, d_k] = [L, d_k]
```

出力の `i` 行目は、「トークン `i` が注目した相手の Value を、重み付きで混ぜた表現」です。

こうして、各トークンに、文脈が混ざり込みます。

第4巻6章で「embedding だけでは独立」と言った、その独立が、ここで解消されます。

「面白かった」のベクトルに、注目した「本」の Value が、強く混ざるのです。

### 4.4　中心式を関数として実装する

以上をまとめると、論文の中心式になります。

```text
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V
```

このシリーズで、最も大切な、一行です。

関数として、実装しましょう。

```python
import torch
import torch.nn.functional as F

def attention(Q, K, V):
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / (d_k ** 0.5)   # [..., L, L]
    weights = F.softmax(scores, dim=-1)               # 合計1の重み
    out = weights @ V                                  # 重み付き和
    return out, weights

# 動作確認
Q = torch.randn(3, 8)
K = torch.randn(3, 8)
V = torch.randn(3, 8)
out, w = attention(Q, K, V)
print("out:", out.shape)        # torch.Size([3, 8])
print("weights:", w.shape)      # torch.Size([3, 3])
print("各行の合計:", w.sum(dim=-1))   # すべて 1 付近
```

関数の中身を、もう一度、式と対応させましょう。

```text
scores = Q @ K.transpose(-2, -1) / (d_k ** 0.5)   ← QK^T / sqrt(d_k)
weights = F.softmax(scores, dim=-1)               ← softmax(...)
out = weights @ V                                  ← ... V
```

3行で、中心式が、そのまま書けています。

`K.transpose(-2, -1)` は、最後の2次元を入れ替えて `K^T` にする書き方です。

なぜ `.T` でなく、こう書くのか。

バッチ付き（`[batch, L, d_k]`）でも動くようにするためです（第2巻5章の回収）。

`.T` は2次元用なので、3次元以上では `transpose` を使います。

最後の `w.sum(dim=-1)` を見てください。

各行の合計が、すべて1になっています。

softmax が、正しく効いている証拠です。

この `attention` 関数が、Transformer のあらゆる Attention の、土台です。

次章からは、これに「自分自身に適用する」「未来を隠す」「複数ヘッドにする」を、足していきます。

### 4.5　本章のまとめ

- 相性スコアは Query と Key の内積。`QK^T` で全トークン対のスコアを一度に計算する（`[L, L]` の表）。
- `sqrt(d_k)` で割るのは、スコアが大きくなりすぎて softmax がとがり、勾配が消えるのを防ぐため（例：`[20,10,0]` は1つに集中）。
- softmax は `dim=-1`（各 Query 行）で取り、合計1の重みにする。`weights @ V` で Value を重み付き和にする。
- 中心式 `softmax(QK^T / sqrt(d_k))V` を、3行の `attention` 関数として実装した。以降の部品の土台になる。
- `K.transpose(-2, -1)` はバッチ付きでも動く `K^T` の書き方。
