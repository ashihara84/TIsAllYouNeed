# 第12章　部品を並べてみる（まだ統合しない）

**この章でわかること**

- 1つの Transformer ブロックの構成の確認
- ブロックを小さく書いて動かす
- なぜ、ここで言語モデルとして通さないのか（第7巻の仕事）

### 12.1　1つの Transformer ブロックの構成

前章で、Transformer ブロックが、できました。

改めて、その中に何が入っているかを、確認しましょう。

これまでの章で作った部品が、すべて、ここに集まっています。

```text
TransformerBlock:
  ├─ Multi-Head Attention（第4〜7章）
  │    ├─ Q/K/V を作る（第3章）
  │    ├─ スケール付き内積 Attention（第4章）
  │    ├─ causal mask（第6章）
  │    └─ 複数ヘッド（第7章）
  ├─ Feed-Forward Network（第10章）
  └─ 残差接続 + LayerNorm で各サブlayer を包む（第11章 / 第3巻）
```

一つのブロックの中に、この巻で作ったものが、ぜんぶ詰まっています。

そして、入力には、トークン embedding に、位置エンコーディング（第8〜9章）を足したものが、入ります。

これで、Transformer に必要な部品が、すべて手元に、揃いました。

第1章で挙げた「部品表」が、全部、埋まったのです。

### 12.2　ブロックを小さく書いて動かす

部品が揃ったことを、実感するため、「embedding ＋ 位置 ＋ ブロック数段」を並べて、shape が通ることを、確認します。

ここで、はっきりさせておきます。

これは **統合（言語モデルとして学習・生成する）ではありません**。

部品が、ちゃんと噛み合うか、の確認です。

```python
import torch
import torch.nn as nn

torch.manual_seed(0)
vocab_size, d_model, n_heads, L = 50, 16, 4, 6

emb = nn.Embedding(vocab_size, d_model)
pos = LearnedPositionalEmbedding(max_len=128, d_model=d_model)   # 第9章
blocks = nn.ModuleList([TransformerBlock(d_model, n_heads) for _ in range(2)])

ids = torch.randint(0, vocab_size, (1, L))   # [batch=1, L]

x = emb(ids)        # [1, L, d_model]
x = pos(x)          # 位置を足す
for blk in blocks:  # ブロックを2段通す
    x = blk(x)
print(x.shape)      # torch.Size([1, 6, 16])  入力と同じ形のまま
```

shape の流れを、追いましょう。

```text
ids   : [1, 6]        （1文、6トークンの ID）
 ↓ embedding
x     : [1, 6, 16]    （各トークンがベクトルに）
 ↓ 位置を足す
x     : [1, 6, 16]    （位置の情報が加わる）
 ↓ ブロック1
x     : [1, 6, 16]
 ↓ ブロック2
x     : [1, 6, 16]    （形は変わらない）
```

embedding → 位置 → ブロック2段、と通しても、shape は `[1, 6, 16]` のまま。

各部品が、同じ `[batch, L, d_model]` を受け取り、同じ形を返すよう、設計してきたおかげです。

だから、いくらでも積み重ねられることが、確認できます。

これが、Transformer が「同じブロックを何段も積む」というシンプルな構造で動く、理由です。

### 12.3　なぜ、ここで言語モデルとして通さないのか

ここで、強い誘惑があります。

「あと少しで、言語モデルになる」。

「出力に語彙サイズの線形層を足して、損失を計算して、学習させてしまいたい」。

実際、`x` に `nn.Linear(d_model, vocab_size)` を足せば、次トークンの予測が出せます。

もう、目の前まで来ているのです。

しかし、この巻では、それを **しません**。

それは **第7巻の仕事** だからです。

第1章で固定したスコープを、ここで守ります。

```text
この巻（第5巻）: 部品を作り、噛み合うことを確認する（ここまで）
第7巻         : 部品を統合し、文字レベル言語モデルとして学習・生成する
```

なぜ、わざわざ分けるのでしょうか。

理由は、2つあります。

**1. 巻の使命を守るため。**

この巻の出口は「部品を作る」ことでした。

統合まで手を伸ばすと、第7巻でやることを、先取りしてしまいます。

「あと少しだから」と手を伸ばすと、際限なく広がります。

だから、ここで、きっぱり止めます。

**2. 第7巻には、独自の重要テーマがあるため。**

第7巻は、ただ統合するだけでは、ありません。

「素手（NumPy）で逆伝播を書いてから、PyTorch に移る」という、対比を扱います。

データの用意、学習ループ、生成、デバッグも、それ自体が、学ぶ価値のあるテーマです。

それらをこの巻に混ぜると、どちらも中途半端になります。

だからこの章は、「部品が揃い、噛み合った」ことを確認するところで、気持ちよく止めます。

「作った。動く。次の巻で、いよいよ統合する」。

その期待を持って、第6巻・第7巻へ進みましょう。

### 12.4　本章のまとめ

- Transformer ブロックには、この巻で作った全部品（Q/K/V・Attention・mask・Multi-Head・FFN・残差・LayerNorm）が集まっている。
- embedding ＋ 位置 ＋ ブロック数段、と並べて、shape が通ることを確認した。部品はすべて噛み合う。
- ただし、言語モデルとしての統合（出力層・損失・学習・生成）は、あえてしない。それは第7巻の仕事。
- 「部品が揃った」ところで止め、統合を第7巻に回すことが、第7巻を生かす。
