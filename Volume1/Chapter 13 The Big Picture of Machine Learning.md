## 第13章　機械学習の全体像

**この章でわかること**

- 機械学習プロジェクト全体の流れ
- 問題定義、データ、前処理、学習、評価、改善、運用の関係
- モデル単体ではなくシステムとして考える必要があること
- Transformer や大規模言語モデルもこの流れの中で使われること

### 13.1　問題を定義する

機械学習を使うとき、最初にやるべきことは「問題を定義する」ことです。何を入力にし、何を出力にし、何を良い予測とみなすかを決めなければならないからです。

たとえば「売上を改善したい」という目的は、そのままでは機械学習の問題になりません。具体化する必要があります。「購入するかどうか」を予測するなら分類問題、「売上金額」を予測するなら回帰問題、「おすすめ商品を選ぶ」ならランキングや推薦の問題です。同じ目的でも、機械学習の問題としてどう定義するかによって、使うデータ・モデル・損失関数・評価指標が変わります。

問題定義で考えるべきことは、次のようなものです。

```text
何を予測したいのか / 入力として何を使えるのか / 出力はカテゴリか数値か
いつの時点で予測するのか / 予測結果を何に使うのか / どのような間違いが重大なのか
```

病気の検出では見逃しが、スパム判定では正常メールの誤分類が、価格予測では大きく外すことが重大かもしれません。機械学習は、データを入れれば自動的に答えが出るものではなく、まず人間が「何を解くべき問題として定義するか」を決める必要があります。

```mermaid
flowchart LR
    A["問題を定義する"] --> B["データを集める"]
    B --> C["前処理する"]
    C --> D["モデルを選ぶ"]
    D --> E["学習する"]
    E --> F["評価する"]
    F --> G["改善する"]
    G --> H["本番で使う"]
    H --> I["劣化を監視する"]
    I --> G
```

### 13.2　データを集める

問題を定義したら、次に必要なのはデータです。機械学習はデータから規則性を学ぶ技術なので、データがなければ学習できません。家の価格予測なら過去の物件情報と価格、スパム判定なら過去のメール本文とラベル、言語モデルなら大量のテキストが必要です。

ここで重要なのは、データは量だけでなく質も重要だということです。大量にあっても、ラベルが間違っていたり、偏りが強かったり、ノイズが多すぎたりすると、モデルもその影響を受けます。また、データが本番環境を代表しているかも重要です。昼間の明るい画像だけで学習したモデルは夜間や暗い室内では弱く、都市部の物件データだけで学習したモデルは地方の物件には合わないかもしれません。

データを集めるときには、予測したい対象に関係するか、本番で出てくるデータに近いか、十分な量があるか、ラベルは正しいか、偏りはないか、個人情報や権利上の問題はないか、を考える必要があります。機械学習では、モデルだけでなくデータの設計が結果を大きく左右します。

### 13.3　データを前処理する

集めたデータは、そのままモデルに入れられるとは限りません。多くの場合、モデルが扱いやすい形に整える必要があります。この作業を前処理と呼びます。

- **欠損値**：欠損している行を除外する、平均値で補完する、欠損していること自体を特徴量にする、などの扱いを決めます。
- **スケーリング**：数値特徴量のスケールが大きく違う（年収8,000,000 と 年齢35 など）と学習が不安定になることがあるので、標準化や正規化で値の範囲をそろえます。
- **カテゴリ値**：地域・商品カテゴリ・会員ランクなどは、one-hot 表現や埋め込みで数値に変換します。
- **画像**：画像サイズをそろえ、ピクセル値を正規化します。
- **自然言語**：トークン化が必要です（「吾輩は猫である」→ 吾輩/は/猫/で/ある → トークンID列）。

前処理での設計が悪いと、モデルの性能は大きく下がります。また、前処理でデータ漏洩が起きることもあります。訓練データとテストデータを分ける前に全データの平均や標準偏差を使って標準化すると、テストデータの情報が訓練側に漏れる場合があります。そのため、前処理は慎重に設計する必要があります。

### 13.4　モデルを選ぶ

データを準備したら、次にモデルを選びます。どのモデルを使うかは、問題の種類、データの量、データの形、必要な性能、計算資源、解釈性などによって変わります。

表形式データでは、線形モデル、決定木、ランダムフォレスト、勾配ブースティング木、ニューラルネットワークなどが使われます。画像では畳み込みニューラルネットワークや Vision Transformer、自然言語では Transformer 系、時系列では統計モデル・RNN・LSTM・Transformer などが使われます。

モデルを選ぶときは、単に高性能なものを選べばよいとは限りません。解釈性が重要な場面（医療や金融でなぜその判断になったかを説明する必要がある場合など）では、単純な線形モデルや決定木が好まれることがあります。一方、画像認識や自然言語処理のような複雑な問題では深層学習モデルが強力です。また、データ量が少ない場合は大きすぎるモデルが過学習しやすく、計算資源が限られている場合は大規模なモデルが使えないかもしれません。

```text
問題に合っているか / データ量に対して大きすぎないか / 性能は十分か
推論速度は問題ないか / 解釈性は必要か / 運用コストは許容できるか
```

モデルは問題を解くための道具です。目的に合った道具を選ぶことが重要です。

### 13.5　学習する

モデルを選んだら、訓練データを使って学習します。ニューラルネットワークなら、「入力をモデルに入れる → 予測を出す → 正解と比較して損失を計算する → 逆伝播で勾配を計算する → 最適化アルゴリズムでパラメータを更新する」を、大量のデータで何度も繰り返します。ミニバッチ学習では、訓練データの一部を取り出して少しずつ更新します。

学習中には、訓練損失と検証損失を見ることが重要です。両方が下がっていれば未知データにも対応できるようになっている可能性があり、訓練損失は下がり続けるのに検証損失が上がり始めたら過学習の兆候かもしれません。

#### PyTorchで確認してみる

ここまで学んだ要素をまとめると、学習ループは次のような形になります。

```python
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

torch.manual_seed(0)

x = torch.randn(40, 3)
y = (x[:, 0] + x[:, 1] > 0).long()

train_x, val_x = x[:30], x[30:]
train_y, val_y = y[:30], y[30:]

train_loader = DataLoader(
    TensorDataset(train_x, train_y),
    batch_size=8,
    shuffle=True,
)

model = nn.Sequential(
    nn.Linear(3, 8),
    nn.ReLU(),
    nn.Linear(8, 2),
)
loss_fn = nn.CrossEntropyLoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

for epoch in range(5):
    model.train()
    for batch_x, batch_y in train_loader:
        logits = model(batch_x)
        loss = loss_fn(logits, batch_y)

        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

    model.eval()
    with torch.no_grad():
        val_logits = model(val_x)
        val_loss = loss_fn(val_logits, val_y)

    print(epoch, "train loss:", loss.item(), "val loss:", val_loss.item())
```

このコードには、データ、モデル、損失関数、最適化、ミニバッチ、検証データがすべて入っています。実際の機械学習システムでは、この骨格に前処理、評価指標、ログ、保存、再学習などが加わります。

学習では、ハイパーパラメータ（学習率、バッチサイズ、エポック数、モデルサイズ、正則化の強さ、Dropout率）も重要で、これらの設定によって学習の安定性や最終性能が大きく変わります。機械学習の学習は、単にボタンを押すだけではなく、損失の推移を見て過学習や学習不足を判断し、必要に応じて設定やデータを見直す作業です。

### 13.6　評価する

学習したモデルは、評価する必要があります。評価とは、モデルがどれくらい目的に合った予測をできるかを確認することです。ここで重要なのは、学習に使っていないデータで評価することです。訓練データで高い性能が出ても、未知のデータに対して性能が出るかを見なければなりません。そのために、検証データやテストデータを使います。

```text
分類：精度、適合率、再現率、F値、混同行列
回帰：MAE、MSE、RMSE、誤差分布
ランキング・推薦：Precision@K、Recall@K、NDCG、クリック率
言語モデル：次トークン予測の損失や perplexity、具体的なタスク（質問応答・要約など）
```

ただし、評価指標は問題の目的に合っていなければなりません。病気の検出では精度だけでは不十分で、見逃しを減らすことが重要なら再現率を重視する必要があります。評価では、本当に測りたい性能を測れているか、評価データは本番データに近いか、どの種類の誤りが多いか、特定の条件で性能が落ちていないか、を考えます。評価は、モデルの良し悪しを確認するだけでなく、次に何を改善すべきかを見つけるための作業でもあります。

### 13.7　改善する

評価の結果、性能が十分でない場合は改善を行います。改善の方法はいくつかあります。

- **データの改善**：データを増やす、ラベルの誤りを修正する、本番に近いデータを追加する、偏りを減らす、ノイズを取り除く。多くの場合、モデル構造を変えるより、データを改善した方が効果が大きいことがあります。
- **特徴量や前処理の改善**：重要な特徴量を追加する、不要な特徴量を削除する、カテゴリ値の扱いやスケーリング、欠損値処理を見直す。
- **モデルの改善**：モデルを大きく/小さくする、層数を変える、正則化を追加する、別のモデル構造を試す。ただし、モデルを大きくすれば常に良くなるわけではなく、データ量が少ないと過学習しやすくなります。
- **学習方法の改善**：学習率を調整する、学習率スケジュールを使う、最適化アルゴリズムを変える、早期終了を使う。

また、評価結果を詳しく見ることも重要です（特定のクラスで間違いが多い、長い文章で性能が落ちる、など）。改善は、闇雲にモデルを変えることではなく、評価結果を見て原因を考え、仮説を立てて次の実験を行う作業です。

### 13.8　本番環境で使う

モデルの評価が十分であれば、本番環境で使うこと（デプロイ）を考えます。学習したモデルを実際のサービスや業務システムに組み込み、ユーザーや業務データに対して予測を行います。

ここで重要なのは、研究や実験で良い性能が出ることと、本番で安定して使えることは別だということです。本番環境では、推論速度、メモリ使用量、計算コスト、安定性、障害時の対応、セキュリティ、説明責任などの制約があります。非常に高性能なモデルでも、1回の予測に10秒かかるならリアルタイム用途には使えないかもしれません。

また、モデルが間違えたときにどうするかも設計が必要です（人間が確認する、低信頼度の予測は保留する、ルールベースの安全策を入れる、ログを残す）。機械学習モデルは間違える可能性があるので、本番環境では出力をそのまま無条件に信じるのではなく、リスクに応じた使い方を設計する必要があります。特に医療・金融・法務・安全に関わる領域では、モデルの誤りが大きな影響を持つことがあります。本番利用では、モデル単体ではなく、システム全体として考えることが重要です。

### 13.9　モデルの劣化と再学習

機械学習モデルは、一度作ったら永久に同じ性能を保つとは限りません。時間が経つと性能が落ちることがあり、これをモデルの劣化と呼びます。

原因の一つは、本番データの分布が変わること（data drift / distribution shift）です。スパム判定では手口が変わり、商品推薦ではユーザーの好みや流行が変わり、価格予測では金利や景気で市場環境が変わり、言語モデルでは新しい固有名詞や流行語が出てきます。

モデルの劣化を防ぐには、本番環境で性能を監視する必要があります（予測精度の変化、入力データの分布、誤りの傾向、ユーザーからのフィードバックを見る）。性能が落ちてきたら、新しいデータでモデルを学習し直す再学習を検討します。

ただし、再学習にも注意が必要です。新しいデータだけで学習すると古い重要な知識を忘れるかもしれず、データの品質が悪いとモデルが悪化するかもしれません。再学習したモデルが本当に良くなったか、テストデータや本番に近い評価で確認する必要があります。機械学習システムは、作って終わりではなく、運用し、監視し、必要に応じて更新するものです。

### 13.10　機械学習システムとして考える

機械学習を理解するとき、モデルだけを見ると不十分です。実際には、機械学習はシステムとして考える必要があり、モデルはその一部にすぎません。機械学習システムには、問題定義、データ収集、前処理、特徴量設計、モデル学習、評価、デプロイ、監視、再学習、運用ルール、人間の確認プロセスなどの要素があります。

たとえばスパム判定システムは、モデルがスパムかどうかを予測するだけでなく、「メールを受け取る → 特徴量を作る → モデルで予測する → しきい値で判定する → 迷惑メールフォルダに移す → ユーザーの訂正を受け取る → 誤判定を分析する → 新しいデータで再学習する」という全体が機械学習システムです。モデルの精度が高くても、前処理が本番で再現できなければ意味がなく、評価データが本番と違っていれば実際の性能は期待外れになるかもしれません。

大規模言語モデルを使う場合も同じです。LLM単体の性能だけでなく、プロンプト設計、検索や外部データとの接続、出力の検証、安全性フィルタ、ログと評価、人間のレビュー、権限管理、情報漏洩対策、コスト管理などを考える必要があります。機械学習は、モデルを作る技術であると同時に、モデルを安全かつ有効に使うシステム設計の問題でもあります。

### 13.11　人間の役割

機械学習ではデータからモデルが学習しますが、人間の役割がなくなるわけではありません。むしろ、人間が設計すべきことはたくさんあります。

問題を定義するのは人間です（何を予測したいのか、その予測を何に使うのか、どのような間違いが許されないのか）。データを用意するのも、評価方法を設計するのも、本番での使い方を決めるのも人間です（モデルの出力を自動で使うのか、人間の確認を挟むのか、誤判定時にどう対応するのか）。

機械学習モデルは、与えられた目的やデータに従って学習しますが、その目的やデータが適切でなければ望ましい結果にはなりません。クリック率だけを最大化するモデルを作れば、ユーザーがクリックしやすいものを出すようになりますが、それがユーザーにとって本当に価値があるとは限らず、不安を煽る情報ばかりが選ばれるかもしれません。つまり、何を最適化するかは人間が慎重に設計する必要があります。AIや機械学習が強力になるほど、人間の役割は「細かい処理を書くこと」から、「目的、評価、制約、責任を設計すること」へ移っていきます。

### 13.12　本章のまとめ

**Transformer への接続**

Transformer も、単体のモデルとしてだけでなく、データ、評価、運用、改善を含む機械学習システムの一部として考える必要があります。どのデータで学習するか、どのタスクで評価するか、出力をどのように利用するか、どのタイミングで再学習するかによって、実用上の価値は大きく変わります。

**ミニ演習**

- この章の PyTorch コードに、訓練精度と検証精度を表示する処理を追加してみましょう。
- 「チャットAIを作る」という目的を、入力、出力、評価指標の形に分解してみましょう。
- モデルの精度は高いのに、システムとして失敗する例を1つ考えてみましょう。

この章では、機械学習の全体像を見ました。機械学習はモデルだけで完結するものではなく、「問題を定義する → データを集める → 前処理する → モデルを選ぶ → 学習する → 評価する → 改善する → 本番環境で使う → 監視する → 必要に応じて再学習する」という流れで進みます。

最初に重要なのは、何を予測したいのかを明確にすることです。次にデータを集め、前処理します（データの質・量・偏り・本番データとの近さが性能に大きく影響）。モデルを選び、訓練データで学習し、検証データやテストデータで評価し、結果を見てデータ・特徴量・モデル・学習方法を改善します。本番環境では、性能だけでなく速度・コスト・安全性・説明責任・運用性も重要です。また、時間が経つとデータ分布が変わり性能が劣化することがあるので、監視と再学習が必要になります。

この章で一番重要な考え方は、次の一文です。

**機械学習は、モデルを作るだけでなく、問題定義、データ、評価、運用までを含む一連のシステム設計である。**

Transformer や大規模言語モデルも、この流れの中にあります。次トークン予測という問題を定義し、大量のテキストデータを用意し、モデルを学習し、評価し、追加学習し、本番システムとして運用します。どれほど高度なモデルでも、データ・評価・運用の設計が不十分であれば望ましい結果にはなりません。機械学習を正しく理解するには、モデルの中身だけでなく、そのモデルがどのような目的で、どのようなデータから学び、どのように評価され、どのように使われるのかを見る必要があります。
