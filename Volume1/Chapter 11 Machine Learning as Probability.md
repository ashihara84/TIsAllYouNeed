## 第11章　確率として見る機械学習

**この章でわかること**

- 機械学習で確率が使われる理由
- 確率分布、尤度、最大尤度推定の直感
- 交差エントロピーと尤度の関係
- 言語モデルが次トークンの条件付き確率を扱うこと

### 11.1　なぜ確率が出てくるのか

機械学習では、確率という考え方がよく出てきます。分類問題ではカテゴリごとの確率（犬：0.87 / 猫：0.13）、スパム判定ではスパムである確率（0.92）、言語モデルでは次に来るトークンの確率分布を出します。

なぜ確率が重要なのでしょうか。機械学習が不確実な問題を扱うからです。画像を見て犬か猫かを判定するとき、暗い、一部しか写っていない、ぼやけている、といった場合は曖昧です。「絶対に犬」と断言するより「犬である可能性が高い」と表現する方が自然です。このように、確率はモデルの不確実性を表すために使われます。

言語モデルでは、確率がさらに中心的です。「今日はとても」の後には、「暑い」「寒い」「楽しい」「眠い」など、さまざまなトークンが来る可能性があり、どれも文脈によっては自然です。したがって言語モデルは「次は絶対にこの単語」と決めるのではなく、候補ごとに確率を出します。

```text
暑い：0.30 / 寒い：0.18 / 楽しい：0.10 / 忙しい：0.08 / 眠い：0.05 ...
```

つまり、機械学習では、曖昧さや不確実性を扱うために確率が必要になります。

```mermaid
flowchart LR
    A["入力"] --> B["モデル"]
    B --> C["候補ごとのスコア"]
    C --> D["確率分布"]
    D --> E["判断や生成に使う"]
```

### 11.2　不確実性を扱う

現実のデータには、ほとんどの場合、不確実性があります。同じ入力に見えても、出力が完全には決まらないことがあります。

商品の売上予測では、同じ商品・価格・曜日・広告費でも、天気・競合・SNSの話題・偶然の要因などで売上は毎回まったく同じにはなりません。家の価格予測でも、似た物件でも売主の事情や買主の好みで価格は完全には一致しません。このような問題では「ただ一つの正解値」を完全に当てることは難しく、モデルはもっともありそうな値や値の分布を予測します。

分類問題でも不確実性があります。「犬：0.52 / 猫：0.48」はモデルがかなり迷っていることを、「犬：0.99 / 猫：0.01」は強く犬だと判断していることを表します。このように、確率は単なる分類結果だけでは表せない「自信の度合い」を表せます。

ただし注意が必要です。モデルが出す確率は、必ずしも現実の確率と完全に一致するわけではありません。「90%」と言っても本当に同じようなケースで90%正解するとは限りません。このズレは、モデルの calibration（確率の較正）の問題です。確率を出すことは便利ですが、その確率がどれくらい信頼できるかも考える必要があります。

### 11.3　確率分布

確率分布とは、複数の可能性に対して、それぞれどれくらい起こりやすいかを割り当てたものです。各確率は0以上で、合計は1になります。

```text
犬：0.70 / 猫：0.20 / 鳥：0.10   （合計 1.00）
```

言語モデルでも、出力は確率分布です。語彙が50,000トークンあるなら、50,000個のトークンに確率を割り当て、すべて足すと1になります。モデルはこの確率分布を使って次のトークンを選びます。

確率分布は、単に「一番ありそうな答え」だけでなく、「他にどんな可能性があるか」も表している点が重要です。次の2つの分布を比べます。

```text
分布A：犬 0.90 / 猫 0.05 / 鳥 0.05  → 強く犬だと判断
分布B：犬 0.40 / 猫 0.35 / 鳥 0.25  → 犬が一番だが、猫や鳥の可能性もかなりある
```

どちらも予測カテゴリは犬ですが、モデルの迷い方や候補の広がりが違います。確率分布を見ることで、この違いがわかります。

### 11.4　尤度

確率を使った機械学習では、「尤度」（likelihood）という考え方が重要になります。尤度とは、観測されたデータが、あるモデルのもとでどれくらいもっともらしいかを表す量です。

例で考えます。あるコインを10回投げたところ、表が9回、裏が1回出ました。この結果を見ると、「表が出る確率は0.5」というモデルよりも、「表が出る確率は0.9」というモデルの方が、このデータを説明しやすそうです。つまり、観測されたデータは、表確率0.9のモデルのもとでよりもっともらしい。この「データのもっともらしさ」が尤度です。

機械学習でも同じです。モデルがデータに対して高い確率を割り当てるなら、そのデータはモデルのもとで尤もらしいと言えます。言語モデルで「吾輩は猫である」という文に含まれる各トークンを高い確率で予測できるなら、この文はモデルにとって尤もらしい文です。尤度は、モデルが観測データをどれくらいうまく説明しているかを見るための考え方です。

### 11.5　最大尤度推定

最大尤度推定（Maximum Likelihood Estimation, MLE）とは、観測されたデータの尤度が最大になるように、モデルのパラメータを決める方法です。手元のデータが最も起こりやすくなるようなパラメータを選びます。

先ほどのコインの例では、10回中表が9回出たデータを最もよく説明する表の確率は、直感的には0.9です。このように、観測されたデータが最ももっともらしくなるようにパラメータを選ぶのが最大尤度推定です。

機械学習でも、多くの学習は最大尤度推定として見られます。分類問題では、正解クラスに高い確率を割り当てるように学習します。正解が犬の画像に「犬：0.90 / 猫：0.10」と出すモデルは正解データに高い確率を割り当てており、「犬：0.10 / 猫：0.90」と出すモデルは低い確率しか割り当てていません。最大尤度の考え方では、正解データに高い確率を割り当てるモデルを良いモデルと見ます。

言語モデルでも同じです。文脈に対して実際に続いたトークン（入力「吾輩は」に対し正解「猫」）に高い確率を出すように学習します。つまり、次トークン予測の学習は、観測されたテキストの尤度を高める学習として見られます。

### 11.6　交差エントロピーとの関係

前の章で、分類問題では交差エントロピー損失を使うと学びました。正解クラスに対する予測確率を `p` とすると、損失は `-log(p)` で、`p` が大きいほど損失は小さくなります。

これは最大尤度推定と深く関係しています。最大尤度推定では正解の確率 `p` を大きくしたい。一方、交差エントロピー損失では `-log(p)` を小さくしたい。`p` を大きくすることと `-log(p)` を小さくすることは、同じ方向の目的です。

```text
正解の確率 p を大きくする  =  -log(p) を小さくする
```

そのため、交差エントロピー損失を最小化することは、正解データの尤度を最大化することと対応します。

厳密には、複数のデータに対しては、各データの確率を掛け合わせたものが尤度になります。しかし、確率をたくさん掛けると非常に小さな値になり扱いにくいので、対数を取ります（確率の積は対数を取ると和になる）。さらに、最大化問題を最小化問題として扱うためにマイナスを付けます。この結果が、負の対数尤度（negative log likelihood）です。分類で使う交差エントロピー損失は、この負の対数尤度と非常に近いものです。つまり、交差エントロピーは単なる便利な損失関数ではなく、「観測された正解データを、モデルが高い確率で説明できるようにする」という確率的な意味を持っています。

### 11.7　「もっともらしさ」を最大化する

最大尤度推定を直感的に言うと、モデルは「実際に観測されたデータがもっともらしく見えるように」学習します。

正解が猫の画像に「猫：0.95 / 犬：0.03 / 鳥：0.02」と出すモデルは、観測された正解「猫」を高い確率で説明しています。一方「猫：0.01 / 犬：0.90 / 鳥：0.09」なら、ほとんど説明できておらず、損失は大きくなります。言語モデルでも、「吾輩は猫である」の各位置で実際に続いたトークン（猫、で、ある）に高い確率を出すように学習し、学習データ中の文章がモデルにとってもっともらしくなります。

ただし注意が必要です。モデルは「真実」を直接最大化しているわけではなく、学習データに現れたパターンの尤もらしさを高めています。学習データに誤りや偏りが含まれていれば、それも学習される可能性があります。つまり、最大尤度の学習は強力ですが、データの品質や偏りに大きく依存します。

### 11.8　言語モデルへのつながり

確率の考え方は、言語モデルを理解する上で非常に重要です。言語モデルとは、簡単にいうと、トークン列に確率を割り当てるモデルです。ある文がどれくらい自然か、ある文脈の次にどのトークンが来やすいかを、確率として扱います。

「今日はとても」の後に来るトークンとして、モデルは確率分布（暑い：0.30 / 寒い：0.20 / ...）を出します。学習時には、実際に続いたトークン（正解「暑い」）に高い確率を出すように更新し、これを膨大なテキストで繰り返します。

文章全体の確率も、次トークン確率の積として考えられます。

```text
P(吾輩は猫である)
= P(吾輩) × P(は | 吾輩) × P(猫 | 吾輩は) × P(で | 吾輩は猫) × P(ある | 吾輩は猫で)
```

ここで `P(猫 | 吾輩は)` は、「吾輩は」という文脈の後に「猫」が来る確率です。このように、言語モデルは文脈付きの次トークン確率を学習します。Transformer は、この次トークン確率を計算するための強力なモデル構造です。

### 11.9　条件付き確率

言語モデルを理解するには、条件付き確率の考え方が重要です。条件付き確率とは、ある条件が与えられたときに、別の事象が起こる確率です。記号では `P(A | B)` と書き、「B が与えられたときに A が起こる確率」を意味します。

たとえば `P(猫 | 吾輩は)` は、「吾輩は」という文脈が与えられたときに次に「猫」が来る確率です。何の文脈もなく「猫」が出てくる確率 `P(猫)` と、「吾輩は」の後に「猫」が出てくる確率 `P(猫 | 吾輩は)` では、まったく違います（後者の方が高いでしょう）。

言語モデルは、文脈を条件として、次のトークンの確率を出します。

```text
P(次のトークン | これまでのトークン列)
（例：P(暑い | 今日はとても)、P(寒い | 今日はとても) ...）
```

この条件付き確率をうまく推定できるほど、言語モデルは自然な文章を生成しやすくなります。Transformer は、Self-Attention によって文脈中の各トークンの関係を扱い、その文脈に基づいて次トークンの条件付き確率を出します。つまり、大規模言語モデルの中心には、条件付き確率の考え方があります。

### 11.10　確率分布からトークンを選ぶ

言語モデルは次トークンの確率分布を出しますが、確率分布を出すだけでは文章は生成されません。実際に次のトークンを選ぶ必要があります。

最も単純な方法は、一番確率が高いトークンを選ぶことです（greedy decoding）。ただし、常に一番高いトークンだけを選ぶと、文章が単調になりやすいです。そこで、確率分布に従ってランダムに選ぶ方法もあります（確率が高いトークンほど選ばれやすいが、低いトークンもたまには選ばれる）。こうすると生成に多様性が出ます。

生成AIでよく聞く temperature や top-k、top-p といった設定は、このトークン選択の仕方に関係します。temperature を高くすると低確率の候補も選ばれやすくなり出力が多様に、低くすると高確率の候補が選ばれやすくなり出力が安定します。

つまり、言語モデルの生成は2段階に分けられます。

```text
1. モデルが次トークンの確率分布を出す
2. その確率分布から実際のトークンを選ぶ
```

この2つは別の処理です。モデルが出す確率分布と、そこからどう選ぶかを分けて考えることが重要です。生成では、この処理を何度も繰り返して文章を伸ばしていきます。

```mermaid
flowchart LR
    A["これまでのトークン列"] --> B["言語モデル"]
    B --> C["次トークンの確率分布"]
    C --> D["選択方法"]
    D --> E["次トークン"]
    E --> F["文脈に追加"]
    F --> A
```

#### PyTorchで確認してみる

```python
import torch

torch.manual_seed(0)

tokens = ["atsui", "samui", "tanoshii", "isogashii", "nemui"]
probabilities = torch.tensor([0.30, 0.20, 0.15, 0.10, 0.25])

greedy_id = torch.argmax(probabilities).item()
sampled_id = torch.multinomial(probabilities, num_samples=1).item()

print("greedy:", tokens[greedy_id])
print("sampled:", tokens[sampled_id])
```

`argmax` は常に最も確率が高い候補を選びます。`multinomial` は確率が高い候補ほど選ばれやすくしつつ、低い候補も選ばれる余地を残します。

### 11.11　確率が高いことと正しいことは違う

機械学習モデルは確率の高い出力を返しますが、確率が高いことと正しいことは同じではありません。これは特に大規模言語モデルを使う上で重要です。

言語モデルは、学習データのパターンから見て「もっともらしい」続きを生成します。しかし、「もっともらしい」ことと「事実として正しい」ことは違います。ある人物について質問したとき、モデルが非常に自然で整った文章で答えても、その内容が事実と違う可能性があります。モデルが真実そのものを参照しているのではなく、学習データに基づく確率的な予測をしているからです。

```text
高確率な文章 ≠ 必ず正しい文章
```

特に、最新情報、専門的な事実、数値、法律、医療、金融、個別の固有名詞に関する情報では注意が必要です。モデルが知らない情報でも、それらしく補ってしまうことがあります（ハルシネーション）。言語モデルは確率的に自然な文章を作るのが得意ですが、正確性を保証する仕組みではありません。そのため、重要な情報を扱う場合には、検索、データベース、一次情報、検証プロセスと組み合わせる必要があります。確率モデルとしての言語モデルを理解すると、この性質が見えやすくなります。

### 11.12　本章のまとめ

**Transformer への接続**

言語モデルとしての Transformer は、文脈を条件として次トークンの確率分布を出すモデルです。生成時には、その確率分布から実際のトークンを選びます。つまり、Transformer の出力を理解するには、「確率が高い候補を出すこと」と「事実として正しいこと」は別である、という見方がとても重要です。

**ミニ演習**

- `P(猫 | 吾輩は)` と `P(猫)` の違いを、条件付き確率の言葉で説明してみましょう。
- 確率が高い文章と事実として正しい文章がズレる例を1つ考えてみましょう。

この章では、機械学習を確率として見る考え方を学びました。機械学習では、不確実な問題を扱うために確率が重要になります。分類問題ではカテゴリごとの確率を、言語モデルでは次に来るトークンの確率分布を出します。

確率分布とは、複数の候補に対してそれぞれどれくらい起こりやすいかを割り当てたものです。尤度とは、観測されたデータがあるモデルのもとでどれくらいもっともらしいかを表す量で、最大尤度推定では、観測データが最ももっともらしくなるようにパラメータを決めます。分類や言語モデルで使う交差エントロピー損失は、正解データの尤度を高める考え方と深くつながっています（正解の確率を高くする＝交差エントロピー損失を小さくする）。

言語モデルは、文脈を条件として次トークンの確率 `P(次のトークン | これまでのトークン列)` を予測します。生成時には、モデルが出した確率分布から実際のトークンを選び、それを繰り返して文章を作ります。

この章で一番重要な考え方は、次の一文です。

**機械学習モデルは、不確実な入力に対して候補ごとの確率を出し、学習では観測された正解データがよりもっともらしくなるようにパラメータを調整する。**

Transformer や大規模言語モデルも、この考え方の上にあります。文脈を入力し、次トークンの確率分布を出し、実際に続いたトークンに高い確率を出せるように学習し、生成時にはその確率分布からトークンを選ぶ。この確率的な見方を持っておくと、Transformer の出力、softmax、交差エントロピー、次トークン予測の意味がかなり理解しやすくなります。
