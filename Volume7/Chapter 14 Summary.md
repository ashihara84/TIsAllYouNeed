# 第14章　まとめ：自分で Transformer を動かせた

**この章でわかること**

- 素手から始めて、ここまで来た道のり
- いま動いているものは、論文のどこに対応するか
- 次の巻（現代の LLM へ）への橋

### 14.1　素手から始めてここまで来た道のり

この巻でたどった道を、振り返りましょう。

```text
素手（NumPy）で逆伝播を手書きし、小さなネットを学習させ切った（第2章）
  ↓ loss.backward() 一行で消える対比（第3章）
PyTorch の道具を整理（第4〜5章）
  ↓
文字レベルのデータを用意（第6章）
  ↓
embedding + 位置（第7章）→ Attention（第8章）→ ブロック（第9章）
  ↓
小さな GPT を組む（第10章）→ 学習ループ（第11章）→ 生成（第12章）
  ↓
デバッグの歩き方（第13章）
```

`loss.backward()` の中身を、一度手で書いたからこそ、その後ずっと、autograd を信頼して使えました。

「便利だから使う」ではなく、「中身を知ったうえで、便利だから使う」。

その安心感が、複雑なモデルを組むときの、支えになりました。

そして、第5巻で作った部品を統合し、ついに、**自分で組んだ Transformer が、自分で文字を生成する** ところまで、到達しました。

### 14.2　いま動いているものは論文のどこに対応するか

完成した小さな GPT と、論文（第6巻）の対応を、確認します。

```text
小さな GPT                          論文 / 第5巻
──────────────────────────────────────────────
トークン + 位置埋め込み（第7章）      →  Input Embedding + Positional Encoding
causal mask 付き Multi-Head（第8章）  →  Masked Multi-Head Attention（Decoder側）
Pre-LN ブロック（第9章）             →  Add & Norm で包んだ Attention + FFN
ブロックの積み重ね（第10章）          →  Decoder スタック（Nx）
出力層 Linear + softmax（第10,12章）  →  Linear + Softmax
```

ここで、大切な気づきがあります。

私たちが作ったのは、論文の Encoder–Decoder のうち、**Decoder 側だけ** を使った言語モデルです。

翻訳のような入力系列が、ありません。

ひたすら「次の文字を予測する」ことに、特化しています。

これが、現代の GPT 系モデルの、基本形（Decoder-only）です。

なぜ Decoder だけで足りるのか、という話は、次の第8巻で扱います。

第6巻4章で、Decoder は「未来を見ない（masked）」と学びました。

あなたが第8章で causal mask を必ず使ったのは、Decoder-only を作っていたから、なのです。

### 14.3　次の巻（現代の LLM へ）への橋

あなたが作った小さな GPT は、数万〜十数万パラメータの、CPU で動くおもちゃです。

一方、いま世界で使われている GPT は、数十億〜数千億パラメータの、巨大なモデルです。

その差は、気が遠くなるほど、大きいです。

しかし――構造は、本質的に、同じです。

embedding ＋ Pre-LN の Transformer ブロック ＋ 出力層。

あなたが手で組んだものを、

- ただ大きくし、
- 膨大なテキストで学習させ、
- その後さまざまな調整（fine-tuning、指示チューニング、RLHF）を加えた、

ものが、現代の LLM です。

```text
あなたの小さな GPT  ──規模を上げ、学習を重ね、調整を加える──>  現代の LLM
```

第8巻「Transformer から現代の LLM へ」では、この橋を、渡ります。

「いま君が触っている GPT は、この全体のどこを削ぎ落とし、何を足した形か」を、回収します。

Decoder-only、事前学習とスケール、fine-tuning、RLHF――それらを、あなたが作ったこの小さな GPT を出発点にして、位置づけていきます。

あなたが手で動かしたものが、現代の巨大な LLM につながっている。

その地図を、最終巻で、描きます。

### 14.4　本章のまとめ

- 素手の逆伝播から始め、第5巻の部品を統合し、自分で組んだ Transformer が、文字を生成するまで到達した。
- 作ったのは Decoder-only の言語モデル（causal mask を使う）。これが現代の GPT 系の基本形。
- 構造は本物の GPT と本質的に同じ。違うのは規模と、その後の調整。
- 次の第8巻で、この小さな GPT を出発点に、現代の LLM への橋を渡る。
