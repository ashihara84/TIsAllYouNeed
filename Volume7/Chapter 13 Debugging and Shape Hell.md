# 第13章　デバッグと shape 地獄の歩き方

**この章でわかること**

- shape を常に印字する習慣
- mask が効いているかを確かめる
- 勾配が流れているかを確かめる
- 小さく作って、大きくする

Transformer の実装で、初学者がいちばんつまずくのが、shape の不一致と、静かなバグ（エラーは出ないが学習しない）です。

この章は、その歩き方を、まとめます。

ここで身につけるデバッグの感覚は、Transformer に限らず、あらゆる実装で、役立ちます。

### 13.1　shape を常に印字する習慣

Transformer のバグの、大半は、shape の不一致です。

`@`（行列積）や `view`、`transpose` の前後で、テンソルの形が想定どおりか。

それを、`print` で、確認する癖をつけます。

```python
print("x:", x.shape)
qkv = self.qkv(x); print("qkv:", qkv.shape)
# 期待する shape をコメントで書いておくと、ずれにすぐ気づく
# x: [B, L, d_model], qkv: [B, L, 3*d_model]
```

期待する shape を、コメントとして、式の横に書いておく。

そうすると、ずれた瞬間に、気づけます。

「ここは `[B, L, 64]` のはずなのに、`[B, 64, L]` になっている」というように。

第2巻から繰り返してきた「shape を追う」習慣が、ここで、最大の武器になります。

Transformer のデバッグは、9割が shape の確認だ、と言っても、過言ではありません。

### 13.2　mask が効いているかを確かめる

causal mask は、効いていなくても、エラーが出ません。

ここが、怖いところです。

mask が効いていないと、未来が見えてしまい、学習が「カンニング」になります。

そして、それは、損失が不自然に速く下がる、生成がおかしい、といった形で、現れます。

「やけに損失が下がるな」と思ったら、mask を疑います。

確かめ方は、Attention の重みを取り出して、上三角（未来）が0になっているかを、見ることです（第5巻6章でやった確認）。

```python
# attention の重みを返すようにして、1サンプルを表示
# 上三角がすべて 0 なら mask は効いている
```

「エラーが出ない＝正しい」では、ありません。

mask のような制約は、明示的に、目で確認します。

これは、とても大切な教訓です。

### 13.3　勾配が流れているかを確かめる

学習が進まないとき、勾配が、ちゃんと流れているかを、確認します。

`backward()` のあとで、パラメータの `.grad` が、`None` でないか。

極端に小さく（または NaN に）なっていないか。

それを、見ます。

```python
loss.backward()
for name, p in model.named_parameters():
    if p.grad is None:
        print("勾配なし:", name)        # どこかで計算グラフが切れている
    # else: print(name, p.grad.abs().mean().item())  # 大きさを見る
```

`grad` が `None` のパラメータがあれば、そこへ、計算グラフがつながっていない、というサインです。

原因としては、`detach` のしすぎ、forward で使われていない、などが考えられます。

第3章で「autograd は連鎖律の自動実行」と理解したことが、ここで効きます。

「勾配が来ない＝グラフがつながっていない」と、分かるからです。

### 13.4　小さく作って大きくする

最後に、最も大切な原則です。

**まず極小で動かし、それから大きくする。**

```text
1. block_size=8, d_model=64, n_layers=2 など、極小の設定でまず動かす
2. 1ステップ forward が通るか
3. loss.backward() が通るか
4. 数百ステップで損失が下がるか
5. 生成がそれらしくなるか
→ ここまで通ってから、初めてモデルやデータを大きくする
```

いきなり大きなモデル・大きなデータで動かそうとすると、どうなるでしょうか。

バグの切り分けが、難しくなります。

「動かない。でも、どこが悪いのか、分からない」という、いちばん辛い状態に、陥ります。

小さく速く回せる設定で、各段（forward・loss・backward・生成）が通ることを、1つずつ確認する。

それから、規模を上げる。

これは、第5巻12章・本巻を通じて取ってきた「小さく作って確かめる」方針の、デバッグ版です。

「小さく作って、確かめて、それから大きく」。

これが、実装で迷子にならないための、いちばんの道しるべです。

### 13.5　本章のまとめ

- Transformer のバグの大半は shape 不一致。式の横に期待 shape をコメントし、`print` で確認する。
- mask はエラーなく壊れる。Attention の重みの上三角が0かを、目で確かめる（「エラーなし＝正しい」ではない）。
- 学習が進まないときは `.grad` を見る。`None` なら計算グラフが切れている。
- まず極小設定で forward → backward → 学習 → 生成を1つずつ通し、それから大きくする。
