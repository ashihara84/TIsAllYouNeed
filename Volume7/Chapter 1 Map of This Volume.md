# 第1章　この巻の地図

**この章でわかること**

- この巻（第7巻）で、最終的に何を作るか
- なぜ「素手 → PyTorch」の二部構成を取るのか
- 素手パートの出口（釘で固定）
- この巻でやらないこと

### 1.1　この巻で作るもの

ここまでの旅を、振り返りましょう。

第3巻で、ニューラルネットを書きました。

第4巻で、言語をベクトルにしました。

第5巻で、Transformer の部品を作りました。

第6巻で、論文を読みました。

設計も、その理由も、部品も、すべて手の内にあります。

残るは、一つです。

**統合して、動かす** こと。

この巻の出口は、はっきりしています。

```text
第5巻で書いた部品を統合し、文字レベル言語モデル（小さな GPT）が、
次の文字を吐くところまで通す。
```

学習したモデルに、種となる文字列を与えると、それらしい続きの文字を、生成する。

そこまでを、自分のコードで、実現します。

「犬が」と入れたら、「走る。」と続ける。

そういう、小さな GPT を、自分の手で動かすのです。

これが、第1巻から続いてきた旅の、到達点です。

### 1.2　なぜ「素手 → PyTorch」の二部構成を取るのか

この巻は、前半と後半で、性格が変わります。

```text
前半（第2章）: 素手（NumPy だけ）で、勾配を手で書いた小さなネットを学習させる
後半（第3章以降）: PyTorch で、部品を統合して小さな GPT を作る
```

なぜ、わざわざ素手から始めるのでしょうか。

**教育効果は、対比から生まれる** からです。

第3巻6章で、`loss.backward()` 一行で逆伝播ができることを、学びました。

でも、その一行の中で、何が起きているのかを、本当に手を動かして確かめた人は、多くありません。

「便利だな」で、済ませてしまいがちです。

素手で逆伝播を書いてみると、`backward()` がどれほどの計算を、肩代わりしてくれているかが、身体で分かります。

自分で書いた、何十行もの勾配計算が、PyTorch だと `loss.backward()` の一行で、消える。

この瞬間の、感動と納得が、この巻の隠れたゴールです。

```text
素手で逆伝播を書く（大変さを知る）
  ↓
PyTorch で loss.backward() に置き換える（一行で消える）
  ↓
「autograd のありがたみ」を身体で理解する
```

別々の巻に分けず、一冊の中で前半・後半に置くのは、この対比を、隣り合わせにするためです。

こうすれば、「PyTorch だけ読みたい」という読者も、冒頭の素手パートを一度眺めるだけで、対比を取り逃しません。

### 1.3　素手パートの出口（釘で固定）

素手パートは、つい手を広げたくなる場所です。

「もっと複雑なネットも、手で書いてみよう」と、どんどん広げたくなります。

だから、出口を、釘で固定します。

```text
素手パートの出口:
  NumPy だけで、勾配を手で書いた小さなネットワークを 1個、学習させ切る。
```

「1個」「学習させ切る」が、手を広げすぎないための、ストッパーです。

そして、重要な制約が、あります。

```text
- Attention まで素手で行かない。
  （マルチヘッド attention の手書き逆伝播は、苦行のわりに学びが薄い）
- 自前の autograd フレームワーク（micrograd 的な自作）も作らない。
  （それは「別の山」。この巻の目的から外れる）
```

なぜ Attention まで素手で行かないのか。

マルチヘッド Attention の逆伝播を手で書くのは、ものすごく大変です。

そして、その大変さのわりに、学べることは、小さな MLP で学べることと、大して変わりません。

苦行になるだけで、効率が悪いのです。

だから、素手で味わうのは、「順伝播・損失・逆伝播・更新の一周を、自分の手が全部触った」という感触、ただそれだけです。

それ以上は、PyTorch に任せます。

素手は **冒頭の一章分のみ** です。

### 1.4　この巻でやらないこと

- Attention の逆伝播を手で書く（素手は小さな MLP 1個まで。第2章のみ）。
- 自前の autograd フレームワークを作る（別の山）。
- 新しい部品概念を導入する（第5巻で完了。この巻は統合）。
- Decoder-only 化の意義・事前学習・fine-tuning・RLHF → **第8巻**。

この巻のゴールは「動かす」ことです。

最先端の性能や、巨大なスケールは、目指しません。

CPU で動く小さな GPT が、学習して文字を生成すれば、大成功です。

完璧な文章でなくて、構いません。

「自分で組んだものが、文字を吐いた」。

その手応えこそが、この巻の宝物です。

### 1.5　本章のまとめ

- この巻の出口は、第5巻の部品を統合し、小さな GPT が文字を生成するまで通すこと。
- 前半は素手（NumPy）、後半は PyTorch。対比から「autograd のありがたみ」を身体で理解する。
- 素手パートの出口は「NumPy で勾配を手書きした小さなネット1個を、学習させ切る」。Attention まで素手で行かない。
- 自前 autograd は作らない。現代 LLM の話は第8巻。性能でなく「動かす」ことがゴール。
