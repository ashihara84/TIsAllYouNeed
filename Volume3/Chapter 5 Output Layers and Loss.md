# 第5章　出力層と損失

**この章でわかること**

- 分類の出力を、softmax で確率分布にすること（第2巻の実装での回収）
- ロジットとは何か
- cross entropy を損失にする理由を、具体的な数で確かめる
- 出力層と損失をつなぐときの、よくある落とし穴
- 1ステップ分の損失を、実際に計算する

### 5.1　分類の出力は softmax（第2巻の回収・実装で）

MLP の最後の層（出力層）は、問題の種類に合わせて、出力の形を整えます。

多クラス分類なら、出力は「各クラスの確率」であってほしいです。

たとえば、犬・猫・鳥の3クラス分類なら、

```text
犬である確率：0.7
猫である確率：0.2
鳥である確率：0.1
```

のように、合計1の確率で出てほしい、ということです。

ところが、出力層が出す生の数値は、そのままでは確率になっていません。

出力層が出す、この生の数値を **ロジット**（logits）と呼びます。

ロジットは、たとえばこんな値です。

```text
犬：2.0
猫：1.0
鳥：-1.0
```

見て分かるとおり、負の値もありますし、合計も1になっていません（2.0 + 1.0 + (-1.0) = 2.0）。

これでは「確率」として使えません。

このロジットを、確率分布に変えるのが **softmax** です。

第2巻7章で、softmax を「数値の列を、合計1の重みに変える関数」として学び、コードでも確かめました。

ここでは、それを「分類モデルの出力層」として使います。

```python
import torch

logits = torch.tensor([2.0, 1.0, -1.0])   # 3クラスの生スコア
probs = torch.softmax(logits, dim=-1)

print(probs)            # 合計1の確率分布
print(probs.sum())      # tensor(1.0000)
```

出力は、たとえば `[0.705, 0.259, 0.035]` のようになります。

確かめてみてください。

- すべて0以上、1以下になっています。
- 合計すると1になります（0.705 + 0.259 + 0.035 = 0.999... ≈ 1）。
- もともと大きかったロジット（犬の2.0）が、いちばん大きい確率（0.705）になっています。

これで、ロジットが「確率分布」に変わりました。

ここで `dim=-1` は、「最後の次元方向に softmax を取る」という指定です。

なぜこの指定が要るのか、と思うかもしれません。

バッチがあるときに、これが重要になります。

たとえば `[batch, クラス数]` の形のとき、「各データごとに、クラス方向で合計1にしたい」のです。

`dim=-1` は、いちばん最後の次元（＝クラス方向）で softmax を取れ、という意味になります。

### 5.2　cross entropy を損失にする

確率分布が出せたら、次に必要なのは、「それが正解にどれだけ近いか」を測る損失です。

分類では **交差エントロピー**（cross entropy）を使います。

第1巻4章・11章で直感を、第2巻9章で形とコードを学んだ、あれです。

考え方は、こうです。

正解クラスに、モデルが割り当てた確率を `p` とします。

このとき、損失は次のようになります。

```text
loss = -log(p)
```

`log` は対数です。

なぜこの形なのか、具体的な数で確かめましょう。

正解クラスの確率 `p` が、いろいろな値のときの損失を計算します。

```text
p = 0.9 → loss = -log(0.9) ≈ 0.105   （正解に高い確率 → 損失は小さい）
p = 0.5 → loss = -log(0.5) ≈ 0.693
p = 0.1 → loss = -log(0.1) ≈ 2.303   （正解に低い確率 → 損失は大きい）
p = 0.01 → loss = -log(0.01) ≈ 4.605  （正解をほぼ無視 → 損失はとても大きい）
```

パターンが見えます。

正解の確率 `p` が1に近いほど、`-log(p)` は0に近づき、損失は小さくなります。

逆に、`p` が0に近いと、損失は急激に大きくなります。

これが、私たちの望む性質です。

「正解に高い確率を与えたモデルほど、損失が小さい」。

学習は損失を小さくする営みでした（第1巻4章）。

だから、cross entropy を小さくしていけば、モデルは正解に高い確率を与えるようになる、というわけです。

### 5.3　出力層と損失をつなぐ

ここで、実装上の、とても大事な注意があります。

初学者が必ずと言っていいほど、はまる落とし穴です。

PyTorch の `nn.CrossEntropyLoss` は、**内部で softmax を行います**。

つまり、`CrossEntropyLoss` は「ロジットを受け取って、自分で softmax してから、cross entropy を計算する」関数なのです。

```text
モデル出力（ロジット） → CrossEntropyLoss（内部で softmax + 交差エントロピー）
```

だから、モデルの出力層では、softmax を **かけずに**、ロジットのまま損失関数に渡すのが、正しい使い方です。

もし、自分で softmax をかけてから `CrossEntropyLoss` に渡すと、どうなるでしょうか。

softmax が二重にかかってしまいます。

一度確率にしたものを、もう一度 softmax する、という変なことになります。

その結果、学習がうまく進まなくなります。

```text
正しい： ロジット → CrossEntropyLoss
誤り  ： ロジット → softmax → CrossEntropyLoss（softmax 二重がけ）
```

この落とし穴は、エラーが出ないので、気づきにくいです。

「なぜか学習が進まない」というとき、まずここを疑ってください。

### 5.4　1ステップ分の損失を計算する（実装）

実際に、ロジットと正解ラベルから、損失を計算してみましょう。

```python
import torch
import torch.nn as nn

loss_fn = nn.CrossEntropyLoss()

# バッチ2件、3クラス分類
logits = torch.tensor([
    [2.0, 1.0, -1.0],   # 1件目の生スコア
    [0.5, 2.5,  0.0],   # 2件目の生スコア
])

# 正解クラス（インデックス）。1件目はクラス0、2件目はクラス1が正解
targets = torch.tensor([0, 1])

loss = loss_fn(logits, targets)
print(loss)   # 1つのスカラー（バッチ全体の平均損失）
```

shape を確認しておきましょう。

```text
logits  : [batch, num_classes] = [2, 3]
targets : [batch]              = [2]    （正解クラスの番号）
```

`targets` は、one-hot ではなく、「正解クラスの番号」であることに注意してください。

1件目の正解はクラス0、2件目の正解はクラス1、という意味です。

`loss_fn` が内部でやっていることを、順を追って見ましょう。

1. まず、各データのロジットに softmax をかけて、確率分布にします。
2. 次に、各データの「正解クラスの確率」を取り出します。
3. その `-log` を計算します（これが各データの損失）。
4. バッチ全体で平均して、1つのスカラーにまとめます。

たとえば、1件目のロジット `[2.0, 1.0, -1.0]` を softmax すると `[0.705, 0.259, 0.035]` でした。

正解はクラス0なので、その確率 0.705 を取り、`-log(0.705) ≈ 0.349` が1件目の損失です。

2件目も同様に計算し、2件の平均が、最終的な損失になります。

この「1つのスカラーの損失」が、次章で勾配を流す出発点になります。

学習とは、第1巻で繰り返し見たとおり、このスカラーを小さくしていく営みです。

このスカラーが小さくなるように、すべてのパラメータを少しずつ動かしていく。

それが、次章からの逆伝播と、学習ループの話です。

### 5.5　本章のまとめ

- 出力層が出す生スコアを、ロジットと呼ぶ。softmax で、ロジットを確率分布に変える（第2巻7章）。
- 分類の損失は、交差エントロピー `-log(正解の確率)`。正解に高い確率を与えるほど、損失は小さい。
- `p=0.9` なら損失 ≈ 0.1、`p=0.1` なら損失 ≈ 2.3。正解を外すほど、急激に大きくなる。
- PyTorch の `nn.CrossEntropyLoss` は内部で softmax を行う。モデル側で softmax をかけず、ロジットを渡す（二重がけ注意）。
- `logits[batch, num_classes]` と `targets[batch]`（正解クラス番号）から、バッチ平均の損失（1つのスカラー）が得られる。これが勾配の出発点。
