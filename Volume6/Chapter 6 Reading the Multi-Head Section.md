# 第6章　Multi-Head Attention の節を読む

**この章でわかること**

- なぜ複数ヘッドか、の著者の説明
- 次元の分割と結合（第5巻7章の対応）
- 計算量の話

### 6.1　なぜ複数ヘッドかの著者の説明

論文は「Multi-Head Attention」の小節で、1つの Attention の代わりに、複数のヘッドを使う理由を、述べます。

要約すると、こうです。

```text
- 1つの Attention（1ヘッド）では、注目が1通りに平均化されてしまう。
- 複数のヘッドを使うと、それぞれが異なる「表現の部分空間」で、
  異なる位置の情報に、同時に注目できる。
```

第5巻7章で「複数の観点で同時に注目する」と説明した、まさに、その利点です。

第5巻7章では、「走る」が、ある観点では「犬」（主語）に、別の観点では「昨日」（時）に注目したい、という例を使いました。

論文は、これを「異なる表現部分空間（representation subspaces）の情報に、異なる位置で同時に注目できる」という言い方を、します。

言葉は少し硬いですが、意味は、あなたが第5巻で得た直感と、同じです。

「1つの頭では1通りの見方しかできない。複数の頭で、いろいろな見方を同時にする」。

その直感に、著者の言葉が、重なります。

### 6.2　次元の分割と結合（第5巻7章の対応）

論文の Multi-Head の構成は、第5巻7章で実装したとおりです。

```text
1. Q, K, V を、それぞれ h 個のヘッドに線形射影する（次元を分割）
2. 各ヘッドで Scaled Dot-Product Attention を行う
3. 全ヘッドの出力を連結（concat）する
4. 最後に線形変換 W_O でまとめる
```

論文では、各ヘッドの次元を `d_k = d_model / h` とします。

論文は d_model=512, h=8 なので、d_k=64 です。

第5巻7章で `512 = 8 × 64` と確かめた、あの分割です。

そして、ヘッドを分割しても、全体の計算量が、1ヘッドの場合とほぼ変わらないように、設計されています。

第5巻7章で「`d_model` を `h` 個に分割するので、計算量を増やさず観点を増やせる」と述べた、その設計です。

並べてみましょう。

```text
論文      : 各ヘッド d_k = d_model / h、h 個に射影 → Attention → concat → W_O
第5巻7章  : split_heads で [B,h,L,d_k] に分け、各ヘッドで attention、結合して W_O
```

実装（第5巻7章の `MultiHeadAttention`）と、論文の記述が、一対一で対応します。

あなたの `split_heads` が、論文の「h 個に射影」。

あなたの `transpose + view` での結合が、論文の「concat」。

あなたの `W_o` が、論文の `W_O`。

すべて、対応しています。

### 6.3　計算量の話

論文は、ヘッドを分割して各ヘッドの次元を小さくすることで、Multi-Head 全体の計算コストが、フル次元の単一ヘッド Attention と、ほぼ同等になる、と述べます。

直感的には、こうです。

1ヘッドで `d_model`(512) 次元の Attention をするのと、`d_model/h`(64) 次元の Attention を `h`(8) 個するのとでは、合計の計算量が、だいたい同じになります。

512次元を1回 vs 64次元を8回。

掛け算すれば、似た規模になる、というわけです。

つまり、「タダ同然で、観点を増やしている」に近いのです。

これは、設計の巧みさで、第5巻7章でも強調した点でした。

なお、論文の別の箇所では、Self-Attention 層全体の計算量を、再帰層や畳み込み層と、比較しています。

その比較は、次章（Why Self-Attention）で扱います。

### 6.4　本章のまとめ

- Multi-Head の理由：1ヘッドだと注目が平均化される。複数ヘッドで、異なる部分空間・異なる位置に、同時注目できる。
- 構成は「h 個に射影 → 各ヘッドで Attention → concat → W_O」。第5巻7章の実装と、一対一で一致。
- 各ヘッド次元 `d_k = d_model / h`（論文は 512/8 = 64）なので、ヘッドを増やしても全体の計算量はほぼ変わらない。
- 第5巻7章の `MultiHeadAttention`（split_heads・W_o）が、論文の記述にそのまま対応する。
