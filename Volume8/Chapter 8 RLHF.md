# 第8章　RLHF：人間のフィードバックで整える

**この章でわかること**

- なぜ教師あり学習だけでは足りないのか
- 報酬モデルという考え方
- 人間の好みで方策を更新する（直感）
- 近年の代替手法の位置づけ（概観）

### 8.1　なぜ教師あり学習だけでは足りないのか

指示チューニング（第7章）で、モデルは、指示に従えるように、なりました。

しかし、まだ課題が、残ります。

「望ましい応答」を、1つ1つ書いて教える、教師あり学習には、限界が、あるのです。

どんな限界でしょうか。

```text
- 「良い応答」を人が毎回書くのは大変で、量も限られる。
- 「何が良いか」は、書いて教えるより「比べて選ぶ」方が、人間には簡単。
  （ゼロから良い答えを書くより、2つの答えのどちらが良いかを選ぶ方が楽）
- 丁寧さ・安全性・正直さといった「好ましさ」は、唯一の正解を書きにくい。
```

3つ目が、特に重要です。

「丁寧で、安全で、正直な応答」とは、何でしょうか。

これには、唯一の正解が、ありません。

「これが100点の応答」と、1つ書くのは、難しいのです。

でも、2つの応答を見せて「どちらが丁寧か」を選ぶのは、人間には、簡単です。

ゼロから書くより、比べて選ぶほうが、ずっと楽。

この「比べて選ぶ」の楽さを、活かせないでしょうか。

そこで、「人間が良し悪しを **比べて** 評価する」情報を使って、モデルをさらに整える方法が、登場します。

それが **RLHF**（Reinforcement Learning from Human Feedback、人間のフィードバックによる強化学習）です。

### 8.2　報酬モデルという考え方

RLHF の鍵は、**報酬モデル**（reward model）です。

考え方を、順を追って、説明します。

まず、同じ指示に対する、モデルの複数の応答を、人間に **どちらが良いか、比べてもらいます**。

この「比較」のデータを、大量に集めます。

```text
指示に対する応答A と 応答B を人間に見せる → 「Aの方が良い」
これを大量に集める
```

「A と B、どちらが丁寧？」「A と B、どちらが正確？」。

人間は、選ぶだけ。

これを、たくさん集めます。

次に、この人間の好みのデータを学習して、あるモデルを作ります。

「応答を入力すると、それがどれくらい好ましいかのスコア（報酬）を出す」モデルです。

これが、報酬モデルです。

いわば、人間の好みを真似た「自動採点者」です。

```text
報酬モデル：応答を入力 → 好ましさのスコアを出力
（人間の「どちらが良いか」を学習して作る）
```

人間が毎回採点するのは、大変です。

だから、人間の好みを学習した「自動採点者」を、作っておくのです。

### 8.3　人間の好みで方策を更新する（直感）

報酬モデルが、できました。

それを使って、言語モデル（応答を生成する側＝方策）を、更新します。

直感は、単純です。

```text
言語モデルが応答を生成 → 報酬モデルがスコアをつける
→ スコアが高くなる方向に、言語モデルを更新する
```

言語モデルが応答を作り、自動採点者（報酬モデル）が点をつける。

その点が高くなるように、言語モデルを、調整する。

「報酬モデルが高く評価する応答を、もっと生成するように」、言語モデルを、調整するわけです。

これを繰り返すと、言語モデルの応答が、人間の好み（報酬モデルが代理する好み）に、沿ったものへと、近づいていきます。

ここで使われるのが、強化学習の手法です。

ただし、注意があります。

報酬を上げることだけを追うと、モデルが、妙な手口で報酬を稼ぐ（不自然な応答に走る）危険が、あります。

採点者の裏をかくような、変な応答を、覚えてしまうのです。

だから、「元のモデルから離れすぎない」よう、制約をかけながら、更新するのが、定番です。

細かいアルゴリズムには、立ち入りませんが、「人間の好みを報酬にして、それを上げる方向に整える」という骨格を、つかめば、十分です。

### 8.4　近年の代替手法の位置づけ（概観）

RLHF は、強力です。

しかし、報酬モデルを作り、強化学習を回す手順は、複雑です。

手間が、かかります。

そこで近年、「報酬モデルや強化学習を、より簡素な形に置き換える」手法も、提案されています。

たとえば、人間の好み（比較データ）から、強化学習を経由せずに、直接モデルを最適化する系統の手法などです。

```text
RLHF        : 比較データ → 報酬モデル → 強化学習で方策を更新（強力だが複雑）
近年の代替   : 比較データから、より直接的にモデルを最適化（簡素化の方向）
```

どれが主流かは、時期によって変わり、研究も、活発です。

ここは、断定を避けます。

共通する本質は、こうです。

「人間の好み（比べて選んだ情報）を使って、モデルの応答を、望ましい方向へ整える」。

手法の詳細や、最新動向は、一次情報を、確認してください。

大事なのは、個々の手法名より、「人間の好みで、応答を整える」という、共通の考え方です。

### 8.5　本章のまとめ

- 教師あり（指示チューニング）だけでは、「良い応答を書いて教える」ことの限界がある。比べて選ぶ方が、人間には簡単。
- RLHF は、人間の比較データから、報酬モデル（自動採点者）を作る。
- その報酬が高くなる方向に、元から離れすぎない制約のもとで、言語モデルを更新する。
- 報酬モデル＋強化学習を簡素化する代替手法もある。本質は「人間の好みで応答を整える」こと。
