# 第10章　文脈長とスケーリングの直感

**この章でわかること**

- 長い文脈を、どう扱うか
- Attention の計算量という制約（第6巻8章の回収）
- 長文脈化の工夫の方向性（概観）

### 10.1　長い文脈をどう扱うか

**文脈長**（context length）とは、何でしょうか。

モデルが一度に見られる、トークン数のことです（第7巻の `block_size` にあたるもの）。

文脈長が長いほど、何ができるでしょうか。

- 長い文書を、一度に読ませられる。
- 長い対話の履歴を、保てる。

文脈長は、LLM の実用性を、大きく左右します。

「100ページの文書を、まるごと読んで要約して」とお願いするには、それだけの文脈長が、必要です。

第7巻で作った小さな GPT は、`block_size` を超えた古い部分を、捨てていました（第7巻12章）。

現代の LLM も、文脈長には、上限があります。

そして、その上限を伸ばすことが、大きな課題で、あり続けています。

「もっと長く読めるようにしたい」というのは、つねにある要求なのです。

### 10.2　Attention の計算量という制約（第6巻8章の回収）

なぜ、文脈長を伸ばすのが、難しいのでしょうか。

第6巻8章で読んだ、Self-Attention の弱点が、効いてきます。

```text
Self-Attention の計算量・メモリは、系列長の2乗に比例する。
（全トークン対の相性 QK^T が [L, L] だから。第5巻4章）
```

なぜ2乗か、思い出しましょう。

`QK^T` は、全トークン対の相性を、計算します（第5巻4章）。

L個のトークンの、全ペアなので、`L × L = L²` 個。

だから、系列長の2乗です。

これが、何を意味するか。

具体的な数で、見ましょう。

```text
文脈長を 2倍 にすると → Attention の計算とメモリは おおよそ 4倍
文脈長を 10倍 にすると → おおよそ 100倍
```

文脈長を2倍にすると、計算は4倍。

10倍にすれば、100倍です。

だから、素朴に文脈長を伸ばすと、すぐに、計算とメモリが、破綻します。

これが、長文脈化の、最大の壁です。

第6巻8章で「長系列での2乗コストは、今後の課題」と読んだ、その課題が、現代でも、中心的なテーマなのです。

論文が予見していた弱点が、いまも、研究の最前線にある、というわけです。

### 10.3　長文脈化の工夫の方向性（概観）

この壁に対して、さまざまな工夫が、研究されています。

原理だけ、方向性を、概観します（詳細・最新は、一次情報を確認してください）。

```text
- 効率的な Attention：全トークン対を真面目に計算せず、近似したり、
  一部だけに注目したりして、2乗のコストを下げる。
- 位置の扱いの改良：学習した長さより長い文脈にも対応しやすい位置表現
  （第5巻8章で触れた相対位置・RoPE などの系統）。
- 計算の工夫：メモリ効率の良い Attention の実装（計算順序の工夫で
  メモリを節約する、など）。
```

これらは、いずれも、何に取り組んでいるのでしょうか。

「Self-Attention の2乗コストと、位置の扱い」という、あなたが第5巻・第6巻で理解した制約に、正面から取り組むものです。

つまり、最先端の長文脈研究も、あなたが知っている部品と、その弱点の上に、立っています。

「全トークン対を計算すると2乗になる。じゃあ、一部だけ計算したら？」。

そういう発想が、効率的な Attention です。

あなたの理解の延長線上に、最先端の研究が、あるのです。

### 10.4　スケーリングとの関係

文脈長も、第4章で見た、スケールの一部です。

モデルサイズ・データ量・計算量に加えて、「どれだけ長い文脈を扱えるか」も、LLM の能力を決める、軸の一つです。

ただし、ここで、重要な注意があります。

文脈を長くできることと、長い文脈を **うまく使える** ことは、別の問題です。

「100ページ入れられる」ことと、「100ページの内容を、ちゃんと使える」ことは、違うのです。

たとえば、長い文脈の真ん中あたりの情報を、モデルが見落としがちになる、といった課題も、知られています。

長い文書を入れても、真ん中の大事な一文を、見落とすかもしれない。

「長く入れられる」だけでなく、「長く入れても、ちゃんと効く」ことが、研究の焦点に、なっています。

容量と、それを活かす能力。

その両方が、大事なのです。

### 10.5　本章のまとめ

- 文脈長は、モデルが一度に見られるトークン数。実用性を大きく左右する。
- 伸ばすのが難しいのは、Self-Attention の計算量・メモリが系列長の2乗に比例するから（第6巻8章。2倍で4倍、10倍で100倍）。
- 長文脈化の工夫は、効率的な Attention・位置表現の改良・メモリ効率の良い実装など。第5巻・第6巻の制約に取り組むもの。
- 「長く入れられる」と「長く入れてもちゃんと効く」は別問題。両方が研究の焦点。
