# 第9章　推論時の工夫

**この章でわかること**

- サンプリングと temperature（再訪）
- top-k / top-p の直感
- KV キャッシュで速くする（直感）

この章は、学習ではなく **生成（推論）** のときの、工夫です。

第7巻12章で生成を実装しましたが、現代の LLM は、そこに、いくつかの工夫を加えています。

これらの工夫は、すべて、あなたが第7巻で作った生成ループの、延長線上にあります。

### 9.1　サンプリングと temperature（再訪）

第7巻12章で、次のトークンを「確率分布からサンプリング」し、「temperature で分布の鋭さを変える」ことを、実装しました（第2巻8章の回収）。

これは、現代の LLM でも、そのまま使われています。

復習しましょう。

```text
temperature 低い : 分布がとがる → 手堅いが単調・繰り返しがち
temperature 高い : 分布が平ら   → 多様だが崩れやすい
```

温度を変えるだけで、出力の「お堅さ／自由さ」を、調整できます。

きっちりした答えが欲しいときは、温度を低く。

創造的な文章が欲しいときは、温度を高く。

あなたが第7巻で書いた仕組みが、そのまま、現代でも使われています。

### 9.2　top-k / top-p の直感

サンプリングを、そのまま行うと、ときどき問題が、起きます。

ごくまれに、「確率の非常に低い、変なトークン」を引いてしまい、文が崩れることが、あるのです。

確率0.001のトークンでも、たまたま、引いてしまうことがある。

すると、そこから文が、おかしくなります。

それを防ぐのが、**候補を絞ってからサンプリングする** 工夫です。

**top-k サンプリング。**

確率の高い、上位 k 個のトークンだけを、候補にします。

それ以外は、捨ててから、サンプリングします。

たとえば k=50 なら、確率上位50個から選び、残りは無視します。

**top-p サンプリング（核サンプリング）。**

確率の高い順に、足していって、合計がある割合 p（たとえば0.9）に達するまでのトークンを、候補にします。

候補の数が、状況に応じて、変わるのが特徴です。

```text
top-k : 上位 k 個に絞る（個数で制限）
top-p : 累積確率 p までに絞る（割合で制限、候補数は可変）
```

どちらも、「変なトークンを引く事故を、減らしつつ、多様性は残す」ための、工夫です。

明らかにありえない候補を、選ぶ前に、ふるい落とす。

そういうイメージです。

temperature と、組み合わせて、使われます。

### 9.3　KV キャッシュで速くする（直感）

生成は、トークンを1つずつ伸ばしていく、逐次的な処理でした（第7巻12章）。

ここに、大きな無駄が、あります。

具体的に、見ましょう。

```text
"犬" → 次を生成
"犬 が" → 次を生成      ← このとき "犬" の Attention 計算をやり直している
"犬 が 走る" → 次を生成  ← "犬" "が" の計算をまたやり直している
```

新しいトークンを1つ足すたびに、これまでのトークン全部の計算を、やり直しています。

これは、無駄です。

「犬」の計算は、最初に1回すれば、その後は変わらないのに、毎回やり直している。

実は、各トークンの Key と Value（第5巻3章の K・V）は、一度計算すれば、その後の生成でも、変わりません。

なぜなら、過去のトークンは、もう確定しているからです。

そこで、計算済みの K・V を、**保存しておいて、再利用** します。

これが **KV キャッシュ**（KV cache）です。

```text
KV キャッシュ：
  過去のトークンの K・V を保存しておく。
  新しいトークンでは、その1つ分だけ K・V を計算し、保存した分と合わせて Attention する。
→ 生成が大幅に速くなる
```

直感としては、「毎回ゼロから計算し直さず、前回までの計算結果を取っておいて、使い回す」ことです。

ノートに計算結果をメモしておいて、次に使う、というイメージです。

生成を、実用的な速度にする、重要な工夫です。

そして、この仕組みの核（K・V は後から変わらない）は、あなたが第5巻で作った Attention の性質から、ちゃんと理解できます。

「Key と Value は、そのトークンが確定したら、もう変わらない」。

第5巻で Q/K/V を作ったあなたなら、これが分かります。

最先端の高速化技術も、あなたの知っている部品の、性質に立っているのです。

### 9.4　本章のまとめ

- 生成時の temperature とサンプリングは、第7巻12章のまま、現代でも使われる。
- top-k（上位 k 個）/ top-p（累積確率 p まで）で候補を絞り、変なトークンを引く事故を減らす。
- KV キャッシュは、過去トークンの K・V を保存・再利用して、逐次生成の無駄をなくす高速化。
- いずれも、第5巻で作った Attention の性質から理解できる、推論時の工夫。
