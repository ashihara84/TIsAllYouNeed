# 第8章　n-gram からニューラル言語モデルへ

**この章でわかること**

- n-gram の考え方を、具体例で
- n-gram の2つの限界
- ニューラル言語モデルという発想
- 固定窓モデルの限界（残る課題）

### 8.1　n-gram の考え方

言語モデルの、最も古典的な形が **n-gram** です。

考え方は単純で、こう割り切ります。

「次のトークンは、直前の n-1 個のトークンだけで決まる」。

それより前は、見ない、と決めるのです。

```text
2-gram（bigram）: 直前の1個から、次を予測
3-gram（trigram）: 直前の2個から、次を予測
```

確率は、どうやって求めるのでしょうか。

大量のテキストの中で、「その並びが何回出たか」を、数えて求めます。

具体例で見ましょう。

```text
P("走る" | "犬 が") = (「犬 が 走る」の出現回数) / (「犬 が」の出現回数)
```

たとえば、大量のテキストの中で、

- 「犬 が」が 1000 回出てきて、
- そのうち「犬 が 走る」が 50 回だった、

としましょう。

すると、

```text
P("走る" | "犬 が") = 50 / 1000 = 0.05
```

「犬 が」の次に「走る」が来る確率は、5%、と求まります。

要するに、過去のテキストでの頻度を、数え上げて、確率の表を作るのです。

n-gram の「学習」とは、この「数えること」です。

ニューラルネットのような、勾配降下による学習は、ありません。

ただ、数えるだけです。

### 8.2　n-gram の限界

n-gram には、本質的な限界が、2つあります。

**1. 長い文脈を扱えない。**

n を大きくすれば、長い文脈を見られます。

しかし、n を増やすと、困ったことが起きます。

「その並び」が、データの中に、ほとんど出なくなるのです。

組み合わせが、爆発的に増えるからです。

たとえば、5-gram（直前4個を見る）なら、4単語の特定の並びを数えることになります。

しかし、そんな特定の4単語の並びは、巨大なテキストでも、数回しか出てこなかったり、一度も出てこなかったりします。

数えられなければ、確率を求められません。

だから現実には、n=3〜5 程度が限界で、それより前の文脈は、捨てるしかありません。

例で見ましょう。

```text
"昔々あるところに……（中略）……そのおじいさんは"
→ 「おじいさん」を予測するのに、ずっと前の「あるところに」を使いたい
→ しかし n-gram では、せいぜい直前数語しか見られない
```

長い物語の、ずっと前の情報を使いたくても、n-gram にはできないのです。

**2. 意味の近さを使えない。**

n-gram は、トークンを「記号」として、数えるだけです。

「犬が走る」を学習しても、「猫が走る」は、まったく別物として扱われます。

「犬」と「猫」が似ている、という情報を、使えないのです。

だから、「犬が走る」をたくさん見ても、「猫が走る」の確率は、別途数えないと分かりません。

知識が、単語の間で、まったく共有されないのです。

第5章で見た embedding のような「意味の近さ」が、n-gram には、ありません。

### 8.3　ニューラル言語モデルという発想

これらの限界を破るのが、**ニューラル言語モデル** です。

発想の転換は、2点あります。

**1. トークンを embedding でベクトルにする**（第5章）。

これにより、「犬」と「猫」の近さを、使えるようになります。

似た単語の知識が、共有されるのです。

「犬が走る」で学んだことが、「猫が走る」にも、自然と効きます。

なぜなら、「犬」と「猫」のベクトルが近いので、似た予測がされるからです。

これで、n-gram の2つ目の限界（意味の近さを使えない）が、解消されます。

**2. 次トークンの確率を、数え上げではなく、ニューラルネットで計算する。**

直前のトークン列のベクトルを入力に、語彙全体への確率分布を出力する関数を、学習で作ります（第7章で見た形です）。

数えるのではなく、関数で計算するのです。

```mermaid
flowchart LR
    A["n-gram<br/>記号を数える"] --> B["ニューラル言語モデル<br/>ベクトル＋学習する関数"]
```

これで、「意味の近さを使えない」という、n-gram の2つ目の限界は解消されました。

残るは、1つ目の「長い文脈」の問題です。

これは、まだ解決していません。

### 8.4　固定窓モデルの限界

初期のニューラル言語モデルは、どういう形だったでしょうか。

「直前の、決まった個数（固定窓）のトークンを embedding して、つなげて、次を予測する」形でした。

たとえば「直前4トークンを見る」と、決め打ちします。

これは embedding の恩恵を受けられます。

意味の近さは使えるようになりました。

しかし、**窓の外は見えない** という、n-gram と同じ弱点を、引きずっています。

窓を4トークンにすれば、5個前の単語は、やはり見えません。

例で見ましょう。

```text
固定窓4:
"……あるところに おじいさん と おばあさん が [住んでいました]"
        ↑ 窓の外（見えない）        ↑ ここ4つだけ見て予測
```

「住んでいました」を予測するのに、直前の4トークンしか見られません。

ずっと前の「おじいさん」は、窓の外なので、見えないのです。

窓を広げれば、入力が大きくなりすぎます。

つまり、「長い文脈をどう扱うか」という問題が、まだ残っています。

文章の最初のほうの情報を、ずっと後ろまで運びたい。

固定窓では、それができません。

この「長い文脈を運ぶ」問題に、正面から取り組んだのが、次章の **RNN** です。

RNN は、固定窓をやめて、「状態を持ち越す」という発想で、原理的にはいくらでも長い文脈を扱おうとしました。

### 8.5　本章のまとめ

- n-gram は「直前 n-1 個から、次を予測」。確率は頻度の数え上げで求める（学習＝数えること）。
- n-gram の限界は2つ：長い文脈を扱えない（n を増やすと並びが出てこない）／意味の近さを使えない（記号として数えるだけ）。
- ニューラル言語モデルは、embedding（意味の近さ）と学習する関数で、2つ目の限界を解消した。
- ただし固定窓モデルは、窓の外を見られないという「長い文脈」の問題を引きずる。
- この「長い文脈を運ぶ」問題に挑むのが、次章の RNN。
