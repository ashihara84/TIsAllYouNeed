# 第10章　RNN は何が辛いのか

**この章でわかること**

- 長距離依存を、うまく運べない問題
- 勾配の消失・爆発
- 逐次処理で、並列化できないという弱点
- 「遠くの単語を直接見たい」という欲求

この章は、この巻のクライマックスの、前半です。

RNN の「辛さ」を、3つ、はっきりさせます。

この辛さが分かれば、次章で Attention が「何を解いたのか」が、すっと腑に落ちます。

逆に言うと、ここをぼんやり読み飛ばすと、Attention のありがたみが、半分も伝わりません。

だから、3つの辛さを、一つずつ、じっくり味わってください。

### 10.1　長距離依存をうまく運べない

言語には、遠く離れた単語どうしの関係（**長距離依存**）が、よくあります。

例で見ましょう。

```text
"私が 昨日 図書館で 借りた 本 は とても 面白かった"
```

「面白かった」の主語は、何でしょうか。

「本」です。

「本 は ... 面白かった」という関係です。

でも、「本」と「面白かった」の間には、多くの単語があります。

「は」「とても」が、間に挟まっています。

RNN は、状態を1ステップずつ持ち越します。

だから、「本」の情報を「面白かった」まで運ぶには、その間のすべてのステップを、情報が生き残ったまま、通り抜ける必要があります。

ところが、途中で状態は、何度も更新されます。

「は」を読み、「とても」を読むたびに、新しいトークンの情報が、状態に混ざります。

そのたびに、古い「本」の情報は、少しずつ薄まっていきます。

```text
本 ──薄まる──薄まる──薄まる──> 面白かった（届くころには情報が弱い）
```

要約メモが、新しい情報でどんどん上書きされて、「本」の記憶が薄れていく、というイメージです。

LSTM/GRU のゲートは、これを和らげます。

「本は大事だから保とう」と、ゲートが判断できるからです。

しかし、系列が長くなるほど、遠くの情報を保つのは、難しくなります。

100単語も離れたら、いくらゲートがあっても、限界があります。

### 10.2　勾配の消失・爆発

前章で、RNN は「時間方向に展開すると、非常に深いネットワーク」になる、と述べました。

第3巻9章で学んだとおり、深いネットワークでは、逆伝播の勾配が、何段も掛け算されます。

そのうちに、勾配が、極端に小さくなる（消失）か、極端に大きくなる（爆発）ことがあります。

RNN は、これが特に起きやすい構造です。

系列が長いほど、展開が深くなります。

100トークンなら、100段。

その100段を、勾配が逆向きに通り抜けるうちに、消えたり暴れたりします。

ここに、二重の苦しさがあります。

```text
長い系列 = 非常に深い展開 = 勾配が消える/爆発する
→ 長距離の関係を「運ぶ」のも辛い（10.1）
→ 長距離の関係を「学ぶ」のも辛い（勾配が届かない）
```

「遠くの単語の関係を学習したいのに、それを学ぶための勾配が、届かない」。

運ぶのも辛く、学ぶのも辛い。

これが、RNN の二重苦です。

第3巻9章の残差接続は、この種の問題を和らげる道具でした。

しかし、RNN の逐次的な構造とは、また別の難しさが残ります。

### 10.3　逐次処理で並列化できない

3つ目の、そして実用上きわめて大きい弱点が、**並列化できない** ことです。

これは、性能や速度に直結する、深刻な問題です。

RNN は「前の状態が決まらないと、次の状態を計算できない」構造です。

状態1を計算してから、状態2。

状態2を計算してから、状態3。

どうしても、順番に計算するしか、ありません。

```text
状態1 → 状態2 → 状態3 → ... → 状態L   （前から順にしか進めない）
```

なぜ、これが問題なのでしょうか。

現代の計算機、特に GPU は、たくさんの計算を **同時に（並列に）** 行うのが得意です。

何千もの計算を、一気に並列でこなせます。

ところが、RNN は逐次的なので、この並列性を、ほとんど活かせません。

「前が終わるまで、次に進めない」ので、一列に並んで、順番待ちをするしかないのです。

系列が長いほど、計算が一直線に伸びて、遅くなります。

大量のテキストで、巨大なモデルを学習したい、という時代の要求からすると、この「並列化できない」は、致命的でした。

どれだけ強力な GPU を、何百台も並べても、RNN の逐次性が、ボトルネック（足かせ）になるのです。

「100人の料理人がいても、1つの鍋を順番にしか使えないなら、料理は速くならない」。

そんなイメージです。

### 10.4　「遠くの単語を直接見たい」という欲求

3つの辛さを、並べてみましょう。

```text
1. 長距離依存：遠くの情報が、運ぶ途中で薄まる
2. 勾配の問題：長い＝深い展開で、勾配が消える/爆発する
3. 逐次処理 ：前から順にしか計算できず、並列化できない
```

これらの根っこには、共通の構造があります。

RNN は、情報を「1ステップずつ、状態を経由して、間接的に」運ぶしかない、ということです。

「本」から「面白かった」へ情報を渡すのに、間のすべてのステップを、通さなければならない。

直接は、結べないのです。

ここで、自然な欲求が生まれます。

```text
間のステップを経由せず、
「面白かった」が「本」を 直接 見られたら いいのに。
```

遠くの単語どうしを、距離に関係なく、直接結びつけたい。

しかも、全トークンの結びつきを、順番に待たず、まとめて（並列に）計算したい。

この欲求に、ぴたりと応えるのが、**Attention** です。

次章で、Attention が具体的に何を足したのかを、見ます。

3つの辛さを、しっかり胸に刻んでおいてください。

次章で、その一つ一つに、Attention がどう応えるかが、明らかになります。

### 10.5　本章のまとめ

- RNN の辛さは3つ。(1) 長距離依存の情報が運ぶ途中で薄まる、(2) 長い＝深い展開で勾配が消失/爆発する、(3) 逐次処理で並列化できない。
- 根っこは「情報を1ステップずつ状態経由で間接的に運ぶ」という構造にある。
- そこから「遠くの単語を直接見たい」「全結びつきを並列に計算したい」という欲求が生まれる。
- この欲求に応えるのが Attention（次章）。3つの辛さを胸に刻んでおく。
