# 第7章　言語モデルとは

**この章でわかること**

- 次のトークンを予測するという、シンプルなタスク
- 条件付き確率としての言語モデル（第1巻11章の回収）
- 言語モデルの損失（cross entropy・第2巻の回収）
- テキストそのものが教師になる、という巧妙さ
- 生成：確率分布からトークンを選ぶ

### 7.1　次のトークンを予測するというタスク

**言語モデル**（language model）とは、ごく単純に言えば、こういうものです。

「これまでのトークン列を見て、次のトークンを予測するモデル」。

例で見ましょう。

```text
入力:  "犬 が 走"
予測:  次は？ → "る" が高確率
```

「犬 が 走」まで見たら、次は「る」だろう、と予測する。

たったこれだけです。

拍子抜けするほど、シンプルです。

しかし、この「次の一語を当てる」を、大量のテキストで延々と学習させると、何が起きるでしょうか。

文法も、知識も、文体も、次第に身についていきます。

「東京は日本の___」と来たら「首都」と予測できるようになる。

これは、知識を獲得した、ということです。

「次の一語を当てる」だけで、結果的に、言語のさまざまな側面を学んでしまうのです。

いま私たちが使っている GPT 系のモデルも、その核は、この次トークン予測です。

第1巻14章で「次の単語を予測するというタスク」「言語モデルは巨大な分類問題」として触れた、あの話が、ここで主役になります。

### 7.2　条件付き確率としての言語モデル（第1巻11章の回収）

言語モデルが出すのは、1つの単語ではありません。

**語彙全体に対する確率分布** です。

「これまでの列を条件として、次が各トークンである確率」を、すべてのトークンについて出します。

これは、第1巻11章で学んだ、条件付き確率です。

具体例で見ましょう。

```text
P(次トークン | これまでのトークン列)

例: P( ● | "犬 が 走る" )
  "る"  → 0.01（もう走るは終わった。低い）
  "。"  → 0.60（文が終わりそう。高い）
  "犬"  → 0.02
  "が"  → 0.01
  ...（語彙全体に確率が割り振られる。合計1）
```

「犬 が 走る」まで来たら、次は「。」が来そうだ、と高い確率を出す。

このとき、語彙の全トークンに対して、確率が割り振られます。

そして、その合計は1になります。

つまり言語モデルは、各位置で「語彙サイズ分のクラスを持つ、分類問題」を解いているのです。

語彙が5万なら、5万クラスの分類です。

「次のトークンは、5万個のうちのどれか」を当てる、巨大な分類。

だから、第1巻で「言語モデルは巨大な分類問題」と言ったわけです。

出力は、第3巻・第5章で見たとおり、ロジット → softmax で得る確率分布です。

```text
モデル出力（ロジット）: 長さ = 語彙サイズ
softmax              : 合計1の確率分布（次トークンの分布）
```

第3巻で作った「ロジットを softmax で確率にする」が、ここでそのまま効きます。

### 7.3　言語モデルの損失（cross entropy・第2巻の回収）

学習の損失は、第3巻5章で使った **交差エントロピー** です。

各位置で、「正解の次トークンに、モデルがどれだけ高い確率を与えたか」を測ります。

```text
loss = -log( P(正解の次トークン) )
```

第3巻5章で学んだ、`-log(正解の確率)` です。

正解トークンに高い確率を与えれば、損失は小さい。

外せば、損失は大きい。

これを、系列の全位置、全データで平均したものが、言語モデルの損失です。

第2巻9章の cross entropy、第3巻5章の `CrossEntropyLoss` が、そのまま効きます。

ここで、言語モデル学習の、とても巧妙な点があります。

正解ラベルを、わざわざ人間が用意しなくても、**テキストそのものが教師になる** のです。

どういうことでしょうか。

「犬 が 走る 。」というテキストがあれば、こう使えます。

```text
入力 "犬"          の正解は "が"
入力 "犬 が"        の正解は "走る"
入力 "犬 が 走る"    の正解は "。"
```

1つ後ろのトークンが、そのまま正解になるのです。

「犬」の次は「が」、「犬 が」の次は「走る」。

正解は、テキストの中に、もとから書いてあります。

だから、人間がラベルを付ける必要がありません。

ラベル付けされていない、大量のテキストを、そのまま学習に使えるのです。

これが、言語モデルが、インターネット上の膨大なテキストで学習できる理由です。

「自分で自分の正解を作る」ので、自己教師あり学習と呼ばれます。

この巧妙さが、現代の巨大な言語モデルを可能にしました（第8巻で詳しく）。

次トークン予測のターゲットの作り方は、第7巻の実装で、さらに詳しく扱います。

### 7.4　生成：確率分布からトークンを選ぶ

学習した言語モデルで、文章を作る（生成する）には、どうすればよいでしょうか。

手順は、こうです。

次トークンの確率分布から、1つを選び、それを入力の末尾に足して、また次を予測する。

これを、繰り返します。

```text
"犬 が" → 次の分布 → "走る" を選ぶ
"犬 が 走る" → 次の分布 → "。" を選ぶ
"犬 が 走る 。" → <eos> → 終了
```

1トークン選んでは足し、また予測する。

このループで、文章が伸びていきます。

```mermaid
flowchart LR
    A["これまでの列"] --> B["次トークンの確率分布"]
    B --> C["1つ選ぶ"]
    C --> D["列の末尾に足す"]
    D --> A
```

ぐるぐる回しながら、文章を1トークンずつ作っていく、というイメージです。

どう選ぶかには、いくつか方法があります。

- いつも最も確率の高いトークンを選ぶ（貪欲）。
- 確率に従って、ランダムに選ぶ（サンプリング）。
- 温度（temperature）で、分布の鋭さを変える。

第2巻8章で、sampling と temperature に触れました。

温度を高くすると、確率の低いトークンも選ばれやすくなり、多様な（でも崩れやすい）文になります。

温度を低くすると、確率の高いトークンばかり選ばれ、手堅い（でも単調な）文になります。

具体的な生成の実装は第7巻、現代の生成の工夫（top-k, top-p など）は第8巻で扱います。

ここでは、「生成とは、次の分布から1つ選んで、末尾に足すことの繰り返し」という骨格を、つかんでください。

### 7.5　本章のまとめ

- 言語モデルは「これまでの列を見て、次のトークンを予測する」モデル。GPT 系の核もこれ。
- 出力は語彙全体への確率分布 `P(次トークン | これまでの列)`。各位置が、語彙サイズ分のクラスを持つ巨大な分類問題。
- 損失は交差エントロピー `-log(P(正解の次トークン))`（第2巻9章・第3巻5章）。
- テキストの1つ後ろが、そのまま正解になる（自己教師）。だからラベルなしの大量テキストで学習できる。
- 生成は「次の分布から1つ選び、末尾に足す」の繰り返し。選び方は貪欲・サンプリング・temperature など。
