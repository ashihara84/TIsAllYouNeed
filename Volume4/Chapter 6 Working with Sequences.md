# 第6章　系列データを扱う

**この章でわかること**

- 系列とは何か（順序が意味を持つ）
- 可変長を、どう扱うか
- 文脈（context）という、重要な考え方
- 系列を行列として見る（shape を追う）

### 6.1　系列とは何か（順序が意味を持つ）

**系列**（sequence）とは、要素が順番に並んだデータです。

言語は、典型的な系列です。

なぜなら、語順が意味を変えるからです。

具体例で、確かめましょう。

```text
"犬 が 猫 を 追う"
"猫 が 犬 を 追う"
```

この2つの文は、まったく同じ単語からできています。

「犬」「が」「猫」「を」「追う」。

使われている単語は、5つとも同じです。

しかし、順番が違うだけで、意味がまるで変わります。

1つ目は、犬が追う側、猫が追われる側。

2つ目は、その逆です。

順番だけで、追う側と追われる側が、入れ替わるのです。

だから、系列を扱うモデルは、「どの単語があるか」だけでは足りません。

「どの順で並んでいるか」も、扱える必要があります。

これは、第3巻まで扱ってきた XOR のような「順番のない入力」とは、本質的に違う点です。

XOR の `[0, 1]` は、2つの数の組でしたが、「順番が意味を持つ」という話ではありませんでした。

系列を扱うことが、言語モデルの中心的な難しさであり、面白さでもあります。

### 6.2　可変長をどう扱うか

言語のもう一つの特徴は、系列の長さが、バラバラだということです。

短い文もあれば、長い文もあります。

```text
"はい。"          → 2 トークン
"犬が公園を走る。"  → 7 トークン
```

人間にとっては当たり前ですが、ニューラルネットにとっては、これが扱いにくいのです。

第3巻で見たように、ニューラルネットでバッチ処理するには、長さをそろえる必要がありました。

きれいな行列にするには、各行の長さが同じでなければならないからです。

そこで、短い系列は `<pad>` で埋めて、バッチ内の最大長にそろえます（第4章で予告したパディングです）。

```text
バッチ内で最大長 = 7 にそろえる
"はい。"          → [はい, 。, <pad>, <pad>, <pad>, <pad>, <pad>]
"犬が公園を走る。"  → [犬, が, 公園, を, 走る, 。, <eos>]
```

「はい。」を、`<pad>` を5つ足して、7トークンにそろえました。

これで、2つの文を、きれいな `[2, 7]` の行列にまとめられます。

ただし、ここで注意があります。

パディングは「中身のない詰め物」です。

だから、モデルがそこに注目しないように、後で覆い隠す（マスクする）必要があります。

`<pad>` の部分まで真剣に計算してしまうと、おかしなことになるからです。

このマスクの考え方は、第5巻・第7巻で Attention を扱うときに、もう一度きちんと出てきます。

いまは「長さをそろえるために埋め、埋めた場所は無視する」と覚えておけば十分です。

### 6.3　文脈（context）という考え方

系列を扱ううえで、最も重要な概念が、**文脈**（context）です。

あるトークンの意味は、その周りのトークンによって決まります。

これを、強く意識してください。

具体例を見ましょう。

```text
"銀行 の 金利"        → 銀行 = お金の機関
"川 の 銀行（土手）"   → 銀行 = 川べり（英語の bank の例）
```

同じ「銀行（bank）」という単語でも、周りの文脈で、意味が変わります。

「金利」と一緒なら、お金の機関。

「川」と一緒なら、土手。

だから、よい言語モデルは、各トークンを「単独」で見てはいけません。

「文脈の中で」見る必要があります。

「bank」というトークンを見たとき、周りの「川」や「金利」を見て、どちらの意味かを判断する。

これが、文脈を読む、ということです。

この「文脈の中で意味を決める」という要求が、のちに Attention という仕組みへ、直結します。

Attention は、まさに「各トークンが、文脈中のどのトークンに注目すべきか」を計算する仕組みだからです。

「bank」を処理するとき、「川」に注目すべきか「金利」に注目すべきか。

それを計算するのが、Attention です（第11章で動機として、第5巻で実装として扱います）。

### 6.4　系列を行列として見る（shape を追う）

前章で、ID 列を embedding すると、`[L, d_model]` の行列になりました。

これが、系列をニューラルネットで扱うときの、基本形です。

各行が1トークンのベクトル、行の並びが系列の順番です。

具体的に、イメージしましょう。

```text
[
  犬のベクトル,      ← 0 番目
  がのベクトル,      ← 1 番目
  走るのベクトル,    ← 2 番目
  。のベクトル,      ← 3 番目
]
shape = [L=4, d_model]
```

上から順に、文の順番どおりに、トークンのベクトルが並んでいます。

バッチ付きなら、`[batch, L, d_model]` です。

この3次元の形が、この先ずっと、Transformer の中を流れます。

実装で確かめましょう。

```python
import torch
import torch.nn as nn

vocab_size, d_model = 100, 8
emb = nn.Embedding(vocab_size, d_model)

# 2文、各長さ5にそろえた ID 列
batch_ids = torch.randint(0, vocab_size, (2, 5))   # [batch=2, L=5]
x = emb(batch_ids)
print(x.shape)   # torch.Size([2, 5, 8])  [batch, L, d_model]
```

`[2, 5]` の ID（2文、各5トークン）を embedding すると、`[2, 5, 8]` になります。

2文、各5トークン、各トークンが8次元のベクトル、というわけです。

ここで、とても大事なことがあります。

いまの段階では、各トークンのベクトルは、**まだ独立** です。

embedding しただけでは、「犬」のベクトルは、周りの「走る」を、一切見ていません。

「犬」のベクトルは、「犬」という単語の情報だけを持っていて、文脈が混ざっていないのです。

前の節で「文脈の中で意味を決める」と言いましたが、embedding の段階では、まだそれができていません。

この「各トークンに、文脈を混ぜ込む」仕事こそ、Attention がやることです。

Transformer は、この `[batch, L, d_model]` を受け取り、Attention で文脈を混ぜ、また `[batch, L, d_model]` を返します。

形は変わらず、中身（各ベクトルが文脈を取り込んだ表現）が更新されるのです。

「bank」のベクトルが、周りの「川」の情報を取り込んで、「土手としての bank」を表すベクトルに変わる。

それが、Attention を通したあとの姿です。

その仕組みは、いよいよ第11章と第5巻で、明らかになります。

### 6.5　本章のまとめ

- 系列は順序が意味を持つデータ。言語は語順で意味が変わる（「犬が猫を追う」と「猫が犬を追う」）ので、順序を扱う必要がある。
- 系列は長さがバラバラ。バッチ処理のため `<pad>` で長さをそろえ、埋めた場所は後で無視（マスク）する。
- 文脈とは、あるトークンの意味を決める周りのトークン。同じ「bank」でも文脈で意味が変わる。
- 系列は `[L, d_model]`（バッチ付き `[batch, L, d_model]`）の行列。各行が1トークン。
- embedding しただけでは各トークンは独立（文脈が混ざっていない）。文脈を混ぜ込むのが Attention の仕事（第11章・第5巻）。
