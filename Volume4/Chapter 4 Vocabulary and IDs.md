# 第4章　語彙と ID

**この章でわかること**

- トークンに ID を振るとは、どういうことか
- ID 列としての文章
- 特殊トークン（開始・終了・パディング）の役割
- ID 列を作って、確かめる

### 4.1　トークンに ID を振る

前章で、トークン化によって、文章がトークンの列になりました。

次に、各トークンに、整数の **ID** を割り当てます。

これは、語彙の中での「背番号」のようなものです。

```text
語彙:
"犬"   → 0
"が"   → 1
"走る" → 2
"。"   → 3
```

ID を振る作業は、難しいことではありません。

語彙（トークンの集合）に、順番をつけて、トークンからその番号を引けるようにする。

それだけです。

そして、逆に、番号からトークンを引く対応も、用意しておきます。

こうすれば、ID 列を、もとの文章に戻せます。

この2つの変換に、名前をつけておきましょう。

```text
トークン → ID : エンコード（符号化）
ID → トークン : デコード（復号）
```

エンコードは「文章を数にする」向き。

デコードは「数を文章に戻す」向きです。

生成では、モデルが ID を出すので、それをデコードして文章に戻します（第7章・第7巻）。

### 4.2　ID 列としての文章

文章は、トークン化と ID 付与を経て、整数の列になります。

流れを、まとめてみましょう。

```text
文章:      "犬 が 走る 。"
トークン:  ["犬", "が", "走る", "。"]
ID 列:     [0, 1, 2, 3]
```

この ID 列が、言語モデルが実際に受け取る入力です。

ここで、前章でも触れた、大事なことを、もう一度確認します。

ID 自体には、意味（近さ）がありません。

`0`（犬）と `1`（が）が隣でも、「犬」と「が」が似ているわけではありません。

ID は、次章の embedding で、意味のあるベクトルに変換されるための「住所」にすぎません。

「住所」というのは、こういう意味です。

embedding は、ID を使って、ベクトルの表（embedding 行列）の中から、対応する1行を引いてきます（第5章）。

ID は、その「何行目を引くか」を指す住所、というわけです。

ID 自体は意味を持たず、ただ住所を指すだけ。

意味は、引いてきたベクトルのほうに載っている。

この役割分担を、覚えておいてください。

### 4.3　特殊トークン（開始・終了・パディング）

実際の言語モデルでは、語彙に「ふつうの単語以外」のトークンを加えます。

これを **特殊トークン** と呼びます。

代表的なものを、挙げます。

**開始トークン**（例: `<bos>` = beginning of sequence）。

系列の先頭を表します。

「ここから文が始まる」という目印です。

**終了トークン**（例: `<eos>` = end of sequence）。

系列の終わりを表します。

生成のとき、「ここで文を終える」という目印にもなります。

モデルが `<eos>` を出したら、生成を止める、という使い方をします。

**パディングトークン**（例: `<pad>`）。

長さの違う文章を、まとめて処理するとき、短い方を埋めて、長さをそろえるための「詰め物」です。

語彙に、これらを加えると、こうなります。

```text
語彙（特殊トークン込み）:
<pad> → 0
<bos> → 1
<eos> → 2
"犬"   → 3
"が"   → 4
"走る" → 5
"。"   → 6
```

特殊トークンに、若い番号（0, 1, 2）を割り当てるのが、よくある作法です。

なぜパディングが必要なのか、もう少し説明します。

第3巻で見たように、ニューラルネットはデータをまとめて（バッチで）流すと効率がよいのでした。

しかし、そのためには、系列の長さをそろえる必要があります。

たとえば、「はい。」（2トークン）と「犬が公園を走る。」（7トークン）を、まとめて流したいとします。

長さがバラバラだと、きれいな行列になりません。

そこで、短い「はい。」を `<pad>` で埋めて、7トークンにそろえるのです（第6章で詳しく扱います）。

### 4.4　ID 列を作って確かめる

エンコードとデコードを、小さく書いて、確かめましょう。

```python
# 語彙（特殊トークン込み）
itos = ["<pad>", "<bos>", "<eos>", "犬", "が", "走る", "。"]   # id -> token
stoi = {t: i for i, t in enumerate(itos)}                       # token -> id

def encode(tokens):
    return [stoi["<bos>"]] + [stoi[t] for t in tokens] + [stoi["<eos>"]]

def decode(ids):
    return [itos[i] for i in ids]

tokens = ["犬", "が", "走る", "。"]
ids = encode(tokens)
print(ids)            # [1, 3, 4, 5, 6, 2]  （<bos> ... <eos>）
print(decode(ids))    # ['<bos>', '犬', 'が', '走る', '。', '<eos>']
```

コードを、順に読みましょう。

`itos` は "id to string"、つまり「ID → トークン」の対応です（リストの位置が ID）。

`stoi` は "string to id"、つまり「トークン → ID」の対応です。

`encode` は、トークン列を ID 列にします。

このとき、先頭に `<bos>`、末尾に `<eos>` を付けています。

`decode` は、ID 列をトークン列に戻します。

結果を見てください。

`[1, 3, 4, 5, 6, 2]` の、先頭の `1` が `<bos>`、末尾の `2` が `<eos>` です。

その間の `3, 4, 5, 6` が、「犬」「が」「走る」「。」です。

こうして、整った ID 列ができました。

この ID 列が、いよいよ次章で、embedding によってベクトルに変換されます。

「住所（ID）」から「意味（ベクトル）」へ、というわけです。

### 4.5　本章のまとめ

- ID は語彙の中でのトークンの背番号。トークン→ID がエンコード、ID→トークンがデコード。
- 文章はトークン化と ID 付与を経て、整数の列になる。これが言語モデルの入力。
- ID 自体に意味はない。意味は次章の embedding で与えられる。ID は「何行目を引くか」を指す住所。
- 特殊トークン（`<bos>`・`<eos>`・`<pad>`）は、系列の境界や、バッチ処理のための長さそろえに使う。
