**この章でわかること**

- トークンとは何か

### 3.1　トークンとは何か

**トークン**（token）とは、言語モデルが扱う最小の単位です。

文章を、この単位に切り分けることを、**トークン化**（tokenization）と呼びます。

「トークン＝単語」だと思いがちですが、必ずしもそうではありません。

トークンを、文字にすることもできます。

単語にすることもできます。

その中間（サブワード）にすることもできます。

どれを選ぶかが、トークン化の設計です。

同じ文を、3つの方式で切ってみましょう。

```text
文章: "犬が走る"

文字単位:    ["犬", "が", "走", "る"]      （4トークン）
単語単位:    ["犬", "が", "走る"]          （3トークン）
サブワード:  ["犬", "が", "走", "る"]      （言語や辞書による）
```

同じ文でも、方式によって、切り方も、トークンの数も変わります。

### 3.2　文字単位・単語単位・サブワード単位

3つの方式には、それぞれ長所と短所があります。

一つずつ、丁寧に見ましょう。

**文字単位。**

文章を、1文字ずつに切ります。

長所は、語彙（トークンの種類）が小さいことです。

日本語なら数千、英語ならアルファベットと記号で百程度です。

そして、未知語が出ません。

どんな単語も、文字に分解できるからです。

たとえ初めて見る単語でも、文字の組み合わせとして必ず表せます。

短所は、系列が長くなることです。

「東京特許許可局」は、文字単位だと7トークンになります。

そして、1トークンあたりの意味が薄くなります。

「東」という1文字だけでは、意味があまり定まりません。

**単語単位。**

文章を、単語ごとに切ります。

長所は、1トークンが1単語なので、意味が濃いことです。

「東京」という1トークンに、はっきりした意味があります。

そして、系列が短くなります。

短所は、語彙が巨大になることです。

世の中の単語をすべて登録しようとすると、何十万語にもなります。

そして、辞書にない単語（未知語）を扱えません。

新しい造語や、珍しい固有名詞、誤字などに、弱いのです。

**サブワード単位。**

文字単位と単語単位の、中間です。

よく出る単語は、そのまま1トークンに。

珍しい単語は、複数の部分（サブワード）に分割します。

たとえば、英語の "unhappiness" なら、"un" "happi" "ness" のように分けられます。

よく出る部分は1トークン、珍しい組み合わせは部分に分かれる、というイメージです。

長所は、語彙のサイズを抑えつつ、未知語も部分に分けて表現できることです。

現代の言語モデルは、ほぼこのサブワード方式を使います。

整理すると、こうなります。

```text
文字単位:    語彙小 / 系列長い / 未知語なし / 意味薄い
単語単位:    語彙大 / 系列短い / 未知語あり / 意味濃い
サブワード:  バランス型。現代の主流
```

### 3.3　語彙（vocabulary）と未知語

**語彙**（vocabulary）とは、モデルが知っているトークンの、全集合のことです。

「このモデルは、これらのトークンを知っている」というリストです。

語彙に含まれないトークンが、入力に現れると、どうなるでしょうか。

それは **未知語**（unknown token）になります。

「知らないトークンが来た」という状態です。

単語単位だと、語彙にない単語は、すべて「未知語」という一つの記号に潰すしかありません。

たとえば、語彙にない珍しい固有名詞「ヌビヌビ村」が来たら、まるごと「分からない」になってしまいます。

情報が、すっかり失われます。

ここで、サブワードの利点が効きます。

サブワード単位なら、未知の単語も、知っている部分（サブワード）の組み合わせとして表現できます。

「ヌビヌビ村」も、「ヌ」「ビ」「村」のような、語彙の中にある部分に分ければ、何とか表せます。

完全には理解できなくても、「村」が含まれることは分かる、というように。

これが、未知語問題を大きく和らげます。

### 3.4　サブワード分割の直感（BPE の考え方）

サブワード分割の、代表的な方法に **BPE**（Byte Pair Encoding）があります。

考え方は、直感的です。

手順を、言葉にしてみましょう。

```text
1. 最初は、すべてを文字単位に分ける。
2. 文章全体で「隣り合って、よく一緒に出る2つ」を探し、それを1つに結合する。
3. これを、何度も繰り返す。
```

簡単な例で、イメージをつかみましょう。

英語で "low", "lower", "lowest" という単語が、たくさんあるとします。

最初は文字単位なので、`l o w`、`l o w e r`、`l o w e s t` です。

このとき、"l" と "o" が、よく一緒に出ています。

だから、"lo" を1つに結合します。

次に、"lo" と "w" がよく一緒に出るので、"low" を結合します。

こうして、頻出する "low" が、だんだん1つのトークンにまとまっていきます。

一方、珍しい組み合わせは、結合されずに、部分のまま残ります。

結果として、「頻度に応じて、ちょうどよい粒度」の語彙が、自動的にできあがります。

よく使う単語はまるごと1トークン、珍しい単語は部分のまま、という、いいとこ取りができるのです。

BPE の具体的な仕組みや、現代の LLM が使うトークナイザの詳細は、第8巻で扱います。

この巻では、「頻度の高いまとまりを、1トークンにしていく」という直感で十分です。

### 3.5　トークン化を小さく試す

雰囲気をつかむため、文字単位の、ごく簡単なトークン化を書いてみましょう。

特別なライブラリは要りません。

```python
text = "犬が走る"

# 文字単位トークン化
tokens = list(text)
print(tokens)   # ['犬', 'が', '走', 'る']

# 語彙を作る（出てきた文字の集合に番号を振る）
vocab = {ch: i for i, ch in enumerate(sorted(set(text)))}
print(vocab)    # {'が': 0, '犬': 1, '走': 2, 'る': 3} のような対応

# トークンを ID 列に変換
ids = [vocab[ch] for ch in tokens]
print(ids)      # [1, 0, 2, 3] のような整数列
```

順を追いましょう。

`list(text)` で、文字列を1文字ずつのリストにします（トークン化）。

`set(text)` で、出てきた文字の種類を取り出し、それに番号を振ります（語彙作り）。

最後に、各文字を、その番号に置き換えます（ID への変換）。

ここで作った `ids`（整数の列）が、言語モデルへの入力の、出発点です。

「犬が走る」という文章が、`[1, 0, 2, 3]` という数の列になりました。

これで、第3巻まで扱ってきたニューラルネットに、渡せる形に一歩近づきました。

次章では、この ID と語彙の関係を、もう少し丁寧に整理します。

### 3.6　本章のまとめ

- トークンは言語モデルが扱う最小単位。文章をトークンに切るのがトークン化。
- 文字単位（語彙小・系列長・未知語なし）、単語単位（語彙大・未知語あり）、サブワード単位（中間・主流）がある。
- 語彙はモデルが知るトークンの集合。語彙外は未知語になる。サブワードはこれを和らげる。
- サブワード（BPE）は「頻出するまとまりを1トークンにしていく」ことで、語彙サイズと未知語のバランスを取る。
- 文章はトークン化を経て、整数（ID）の列になる。詳細なトークナイザは第8巻。
